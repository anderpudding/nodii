## 1. 배경과 목표

### 1.1 배경
- 투두메이트를 쓰는 가장 큰 이유는 **모바일과 PC가 연동된다는 점**이었음.
- 그런데 PC 버전이 유료 구독으로만 제공되도록 바뀌면서, 대체할 앱을 직접 만들기로 함.

### 1.2 제품 비전
> **Nodii**: 모든 기기에서 같은 하루를 보여주는, 가볍고 깔끔한 날짜 기반 투두 앱

### 1.3 MVP 목표
1. macOS 데스크톱에서 투두메이트의 **핵심 흐름**(목표별 할 일, 캘린더, 루틴)을 매일 쓸 수 있는 수준으로 만든다.
2. 처음부터 **계정과 클라우드 저장**을 갖춰서, 나중에 모바일 앱을 붙일 때 서버를 거의 바꾸지 않아도 되게 한다.
3. 심사를 통과해서 **Mac App Store에 출시**한다.

### 1.4 투두메이트 대비 차별화 포인트 (리뷰 불만에서 도출)
| 투두메이트 리뷰 불만 | Nodii의 대응 |
|---|---|
| 목표(카테고리)를 삭제하면 과거 할 일도 영구 삭제됨 | 목표는 **보관(archive)** 처리하고 과거 기록은 보존 |
| 색상 옵션 부족, 원하는 색 코드를 쓸 수 없음 | 프리셋 색상 + **HEX 코드 직접 입력** |
| 기기 간 동기화가 불안정함 | 서버를 기준 데이터로 두고 **실시간 반영** |
| M1 Mac 설치 시 멈춤 | Apple Silicon과 Intel을 모두 지원하는 Universal 빌드 |

## 2. 범위

### 2.1 MVP에 포함
- 계정(이메일 인증 코드로 가입·로그인, 로그아웃, 계정 삭제)
- 목표(카테고리) 관리
- 날짜별 할 일, 지난 미완료 할 일 가져오기
- 월간 캘린더 뷰
- 루틴(반복 할 일)
- 클라우드 저장과 실시간 동기화
- 기본 설정
- Mac App Store 출시(앱 샌드박스, 심사용 데모 계정, 개인정보처리방침·지원 페이지, TestFlight 베타)

### 2.2 MVP에서 제외 (다음 버전 후보)
타이머 · 일기 · 친구/피드/스티커 · AI 추천 · 위젯 · 푸시 알림 · Windows 버전 · **모바일 앱** · 오프라인 상태에서 쓰기 · Google/Apple 로그인

### 2.3 용어
| 용어 | 정의 |
|---|---|
| 목표 (Goal) | 할 일을 묶는 카테고리. 이름과 색상을 가짐 (투두메이트의 "목표") |
| 할 일 (Todo) | 특정 **날짜**에 속하는 한 번짜리 항목. 반드시 하나의 목표에 속함 |
| 루틴 (Routine) | 반복 규칙을 가진 항목. 규칙에 해당하는 날짜마다 목록에 자동으로 나타남 |
| 루틴 기록 (Routine Log) | 특정 날짜의 루틴을 완료했거나 건너뛰었다는 기록 |
| 날짜 (Date) | 사용자 **로컬 달력 기준** 날짜 (시각이 아님) |
| 인증 코드 (OTP) | 이메일로 받는 6자리 일회용 코드. 비밀번호 대신 사용 |

## 3. 사용자와 대표 시나리오

**주 사용자:** 하루 단위로 할 일을 계획하고, 주로 맥 앞에서 일하는 학생이나 직장인

| # | 시나리오 |
|---|---|
| S1 | 아침에 앱을 열면 **오늘** 날짜가 선택되어 있고, 목표별로 오늘 할 일과 루틴이 보인다. |
| S2 | 목표 옆 `+`를 누르거나 단축키로 할 일을 빠르게 추가하고, 체크해서 완료한다. |
| S3 | 못 끝낸 할 일을 "내일로" 미룬다. |
| S4 | 월간 캘린더에서 날짜별 달성 현황을 보고, 날짜를 눌러 그날 목록으로 이동한다. |
| S5 | "매주 월·수·금 운동" 같은 루틴을 한 번 만들어 두면 해당 요일마다 자동으로 나타난다. |
| S6 | 며칠 동안 못 끝낸 할 일이 쌓였을 때, 오늘 화면의 "지난 미완료 할 일 N개 가져오기" 버튼으로 한 번에 오늘로 옮긴다. |
| S7 | (나중에) 폰 앱에서 체크한 내용이 맥에 바로 반영된다. MVP에서는 앱 두 개를 띄우거나 재로그인해서 확인한다. |

## 4. 기능 요구사항

우선순위는 MoSCoW 기준입니다. **M**ust(필수) · **S**hould(가능하면 포함) · **C**ould(여유 있으면) · **W**on't(이번엔 안 함)

### 4.1 계정 (AUTH)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| AUTH-01 | 이메일을 입력하면 **6자리 인증 코드(OTP)**가 발송되고, 코드를 입력하면 가입과 로그인이 한 번에 된다. 비밀번호는 없다 | M |
| AUTH-02 | 앱을 다시 열어도 로그인 상태가 유지된다 | M |
| AUTH-03 | 로그아웃할 수 있고, 로그아웃하면 로컬에 캐시된 데이터도 지운다 | M |
| AUTH-04 | 첫 로그인 때 기본 목표 1개("할 일")를 자동으로 만든다 | M |
| AUTH-05 | Google 또는 Apple로 로그인할 수 있다 | W (v2) |
| AUTH-06 | 앱 안에서 계정과 모든 데이터를 삭제할 수 있다 (공개 배포 필수 요건) | M |
| AUTH-07 | 코드가 틀렸거나 만료되면 안내하고, 코드 재전송은 60초가 지난 뒤 할 수 있다 | M |
| AUTH-08 | App Store 심사자가 메일함 없이도 로그인할 수 있도록, **심사 전용 데모 계정**만 이메일+비밀번호로 로그인할 수 있다. 일반 사용자에게는 비밀번호 입력란이 보이지 않는다 | M |

### 4.2 목표 (GOAL)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| GOAL-01 | 목표를 만들고, 이름과 색상을 수정할 수 있다 | M |
| GOAL-02 | 프리셋 팔레트에서 색상을 고를 수 있다 | M |
| GOAL-03 | HEX 코드(#RRGGBB)로 색상을 직접 입력할 수 있다 | S |
| GOAL-04 | 드래그해서 목표 순서를 바꿀 수 있다 | S |
| GOAL-05 | 목표를 **보관**할 수 있다. 보관한 목표는 새 할 일 목록에서 숨기지만, 과거 날짜에서는 기존 할 일이 그대로 보인다 | M |
| GOAL-06 | 목표를 완전히 삭제할 때는 확인 창을 띄우고, 속한 할 일과 루틴이 함께 삭제된다는 사실과 개수를 안내한다 | S |
| GOAL-07 | 할 일은 목표 없이 존재할 수 없으므로, **활성 목표는 항상 1개 이상** 유지한다. 마지막 활성 목표는 보관하거나 삭제할 수 없다 | M |

### 4.3 할 일 (TODO)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| TODO-01 | 선택한 날짜의 특정 목표에 할 일을 추가할 수 있다 (제목 1~200자). **목표 없는 할 일은 허용하지 않는다** | M |
| TODO-02 | 체크해서 완료하거나 완료를 취소할 수 있다 | M |
| TODO-03 | 제목을 인라인으로 수정할 수 있다 | M |
| TODO-04 | 할 일을 삭제할 수 있고, 삭제 직후 몇 초간 "실행 취소"를 제공한다 | M / S(실행 취소) |
| TODO-05 | 할 일의 날짜를 바꿀 수 있다: "내일로", "오늘로", "날짜 선택" | M |
| TODO-06 | 같은 목표 안에서 드래그해서 순서를 바꿀 수 있다 | S |
| TODO-07 | 할 일을 다른 목표로 옮길 수 있다 | C |
| TODO-08 | 할 일을 다른 날짜로 복제할 수 있다 ("다른 날 또 하기") | C |
| TODO-09 | 화면은 목표 순서대로 묶고, 목표 안에서는 사용자가 정한 순서대로 보여준다 | M |
| TODO-10 | 지난 미완료 할 일은 **자동으로 이월하지 않는다.** 대신 오늘 화면에 "지난 미완료 할 일 N개 가져오기" 버튼을 보여주고, 누르면 최근 7일 안의 미완료 할 일(루틴과 보관한 목표의 할 일은 제외)을 한 번에 오늘로 옮긴다. 옮긴 할 일은 각 목표의 맨 아래에 붙고, 가져올 할 일이 없으면 버튼을 숨긴다 | S |

### 4.4 캘린더 (CAL)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| CAL-01 | 월간 캘린더를 보여주고 이전 달과 다음 달로 이동할 수 있다 | M |
| CAL-02 | 날짜 칸마다 그날의 **남은 항목 수**(할 일 + 루틴)를 표시하고, 모두 끝낸 날은 완료 표시를 한다 | M |
| CAL-03 | 날짜를 누르면 그날의 목록이 열린다. 오늘 날짜는 강조한다 | M |
| CAL-04 | "오늘" 버튼으로 오늘 날짜로 바로 돌아올 수 있다 | M |
| CAL-05 | 주 시작 요일(일요일 또는 월요일)을 설정에 따라 적용한다 | S |
| CAL-06 | 할 일을 캘린더의 날짜 칸으로 드래그해서 날짜를 옮길 수 있다 | C |

### 4.5 루틴 (ROUT)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| ROUT-01 | 목표, 제목, 반복 규칙, 시작일, (선택) 종료일로 루틴을 만든다 | M |
| ROUT-02 | 반복 규칙: **매일 / N일마다** | M |
| ROUT-03 | 반복 규칙: **매주 특정 요일(여러 개 가능) / N주마다** | M |
| ROUT-04 | 반복 규칙: **매월 특정 일(여러 개 가능)**. 그 날짜가 없는 달은 **그 달 말일에 표시**한다 (예: "매월 31일"은 30일까지 있는 달에는 30일, 2월에는 28일 또는 29일) | S |
| ROUT-05 | 규칙에 해당하는 날짜의 목록에 루틴이 할 일과 같은 형태로 나타나고, 루틴임을 아이콘으로 구분한다 | M |
| ROUT-06 | 특정 날짜의 루틴을 완료하거나 완료를 취소할 수 있다 | M |
| ROUT-07 | 특정 날짜의 루틴만 "이날은 건너뛰기" 할 수 있다 | S |
| ROUT-08 | 루틴을 수정할 수 있다. **제목과 목표**를 바꾸면 모든 날짜에 바로 적용한다. **반복 규칙**(주기, 요일, 일, 시작일)을 바꾸면 적용 범위를 사용자에게 묻는다.<br>① **과거까지 모두 적용**: 모든 날짜에 새 규칙을 적용한다. 새 규칙에 맞지 않는 날짜의 완료 기록은 지우지 않고 화면에서만 숨긴다<br>② **오늘부터 적용**: 어제까지는 기존 규칙과 완료 기록을 그대로 보여주고, 오늘부터 새 규칙을 적용한다<br>루틴 시작일이 오늘이거나 그 이후라서 과거 날짜가 없으면 묻지 않고 바로 적용한다 | M |
| ROUT-09 | 루틴 종료: "오늘부터 그만하기"(종료일 지정, 과거 기록 유지)와 "완전 삭제" 중 고를 수 있다 | M |
| ROUT-10 | 루틴 목록 화면에서 전체 루틴을 한눈에 보고 관리할 수 있다 | S |

### 4.6 동기화 (SYNC)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| SYNC-01 | 모든 데이터는 클라우드에 저장하고, 같은 계정으로 로그인한 어느 기기에서든 똑같이 보인다 | M |
| SYNC-02 | 사용자의 조작은 네트워크 응답을 기다리지 않고 **즉시 화면에 반영**(낙관적 업데이트)하고, 실패하면 되돌린 뒤 알린다 | M |
| SYNC-03 | 다른 기기나 세션에서 생긴 변경이 **몇 초 안에** 자동 반영된다 (실시간) | S |
| SYNC-04 | 네트워크가 끊기면 상단에 오프라인 표시를 하고, 마지막으로 불러온 데이터는 읽을 수 있다 | S |
| SYNC-05 | 오프라인 상태에서도 쓰기를 허용하고, 다시 연결되면 자동으로 동기화한다 | W (v2) |

### 4.7 설정과 기타 (SET)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| SET-01 | 주 시작 요일을 설정할 수 있다 | S |
| SET-02 | 테마: 라이트 / 다크 / 시스템 설정 따르기 | S |
| SET-03 | 키보드 단축키: `⌘N` 새 할 일, `⌘T` 오늘로 이동, `←/→` 이전·다음 날, `⌘,` 설정 | S |
| SET-04 | 메뉴 막대(트레이)에서 할 일을 빠르게 추가할 수 있다 | C |
| SET-05 | 업데이트는 **Mac App Store가 담당**하고, 앱 자체 업데이트 기능은 넣지 않는다. 대신 서버에 설정한 최소 지원 버전보다 앱 버전이 낮으면 "App Store에서 업데이트해 주세요" 안내와 App Store 이동 버튼을 띄운다 | S |
| SET-06 | UI 언어: 한국어 (영어는 이후) | M |
| SET-07 | 설정 화면에서 개인정보처리방침, 이용약관, 지원 페이지(문의), 앱 버전을 볼 수 있다 | M |

## 5. 비기능 요구사항

| ID | 분류 | 요구사항 | 목표치 / 검증 방법 |
|---|---|---|---|
| NFR-01 | 성능 | 앱을 켜고 오늘 목록이 보일 때까지 걸리는 시간 | 캐시가 있으면 1초 이하, 처음이면 2초 이하 |
| NFR-02 | 성능 | 체크, 추가 같은 조작이 화면에 반영되는 시간 | 100ms 이하 (낙관적 업데이트) |
| NFR-03 | 성능 | 월 이동 시 캘린더 표시 시간 | 300ms 이하 |
| NFR-04 | 자원 | 설치 파일 크기 / 대기 중 메모리 | 15MB 이하 / 150MB 이하 |
| NFR-05 | 호환성 | 지원 OS | macOS 12 이상, Apple Silicon과 Intel (Universal 빌드) |
| NFR-06 | 보안 | 다른 사용자의 데이터에 접근 불가 | 모든 테이블에 RLS 적용, 정책 테스트로 검증 |
| NFR-07 | 보안 | 인증 토큰 저장 위치 | 앱 전용 데이터 폴더에 저장 (v2에서 macOS 키체인으로 이전) |
| NFR-08 | 정확성 | 날짜와 시간대 | 할 일 날짜는 로컬 달력 날짜로 저장해서, 시간대가 바뀌어도 날짜가 밀리지 않음 |
| NFR-09 | 확장성 | 모바일 앱을 추가할 때 | DB 스키마와 API 변경 없이 클라이언트만 추가 |
| NFR-10 | 유지보수 | 도메인 로직(반복 규칙 계산 등) | 순수 TypeScript로 분리하고 단위 테스트 커버리지 90% 이상 |
| NFR-11 | 비용 | 운영비 | Supabase 무료 플랜으로 시작하고, 사용량(MAU, DB 용량)이 한도의 80%에 닿으면 유료 플랜 전환을 검토. Apple Developer Program은 이미 보유 |
| NFR-12 | 신뢰성 | 데이터 손실 | 저장이 실패하면 반드시 사용자에게 알리고, 조용히 유실되는 일이 없어야 함 |
| NFR-13 | 배포 | Mac App Store 요건 | **App Sandbox**를 켜고 권한은 필요한 것(외부 네트워크 연결)만 요청. 암호화 수출 규정은 HTTPS만 사용하므로 "해당 없음"으로 신고. App Store 심사 가이드라인 위반 없이 첫 제출에서 통과하는 것을 목표로 함 |
| NFR-14 | 개인정보 | 법적 고지 | 개인정보처리방침, 이용약관, 지원 페이지를 웹에 게시하고 앱과 App Store Connect에 링크. App Store 개인정보 라벨에 수집 항목(이메일, 사용자 콘텐츠)을 정확히 신고하고 추적(tracking)은 하지 않음. 계정을 삭제하면 모든 데이터를 삭제 |
| NFR-15 | 신뢰성 | 인증 메일 발송 | Supabase 기본 메일 서버 대신 커스텀 SMTP를 사용하고, 발신 도메인에 SPF와 DKIM을 설정해서 스팸함으로 가지 않게 함. 발송 후 1분 안에 도착 |

## 6. 제약과 가정
- **제약:** 1인 개발(+Claude), React/TypeScript 중심, 초기에는 무료 인프라
- **가정:** MVP 사용자는 대부분 온라인 상태에서 앱을 사용한다 (그래서 오프라인 쓰기는 v2로 미룸)
- **가정:** 한 사용자의 데이터 규모는 목표 20개 이하, 하루 할 일 30개 이하, 루틴 50개 이하
- **리스크:** Supabase 기본 메일 서버는 테스트용이라 발송량 제한이 매우 낮음 → 공개 전에 커스텀 SMTP 설정이 필수 (NFR-15)
- **리스크:** Supabase 무료 플랜은 7일 동안 활동이 적으면 프로젝트가 일시정지됨. 실사용자가 생기면 해당하지 않지만, dev 프로젝트는 주의
- **리스크:** App Store 심사에 보통 수일이 걸리고 거절될 수 있음 → 출시 일정에 심사 기간을 넣고, 급한 버그 수정도 심사를 거친다는 점을 감안해 TestFlight로 충분히 검증
- **리스크:** 심사자는 인증 메일을 받을 수 없음 → 심사 전용 데모 계정 필요 (AUTH-08)

## 7. MVP 완료 기준 (Acceptance)
1. S1~S6 시나리오를 실제 맥에서 끝까지 수행할 수 있다.
2. 앱 두 개(또는 두 대의 맥)에 같은 계정으로 로그인했을 때, 한쪽의 변경이 다른 쪽에 반영된다.
3. 본인이 **1주일 동안 투두메이트 대신 Nodii만 쓸 수 있다.**
4. TestFlight 빌드를 **개발에 쓰지 않은 다른 맥**에 설치하고, 샌드박스 환경에서 새 계정 가입과 동기화가 정상 동작한다.
5. App Store 심사를 통과해서 스토어에서 내려받아 사용할 수 있다.
