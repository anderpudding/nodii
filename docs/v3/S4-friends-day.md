> 기준: `docs/16-v3-social-plan.md` SOC-20~38·62(할 일 신고)·D5·D14~D19·D21·D22·D25·D29·D30, S1 RLS(`S1-db.md` §4 친구 SELECT 정책), S2·S3 결과. 화면: `docs/design/screens.md`·`mobile-screens.md`의 v3 절, `components.md` "v3 소셜"(`GoalMark`·`Avatar`·`AvatarRow`·월 제목 버튼·공개 범위 세그먼트), `tokens.md` §9. 규칙: `AGENTS.md` §5 "소셜 (v3)"·§6.

## 0. 범위

**완료 기준(계획서 §8): 맞팔로우·팔로워·나만이 의도대로 보이고, 동그라미가 쓰이던 모든 화면에 범위 아이콘이 나오며, 끈 사람은 아바타 줄에서 빠지고 정한 순서가 두 기기에 같이 보인다.** 두 앱 모두.

- **한다**:
  - 목표 공개 범위 고르기(목표 추가·편집 세그먼트, 처음 공개 안내)
  - `GoalMark`로 모든 목표 동그라미 바꾸기
  - iOS 목표 편집·추가를 하위 화면으로, 무지개 색상 선택기(두 앱)
  - 월 제목 = 오늘 버튼(D30), 날짜 줄 재배치와 고정 줄 없애기(SOC-37), 오프라인 토스트(D19)
  - 오늘 탭 아바타 줄과 친구의 하루(읽기 전용)
  - "오늘에 보일 사람"
  - 사람 하루 페이지 본문(캘린더·목록)과 iOS 머리 접힘
  - 친구 할 일 신고
- **하지 않는다**: 반응 하트·`react` 호출(S5 — 친구 목록의 끝낸 줄 오른쪽은 비워 둠), 알림 탭 내용(S5), 푸시(S6), 전체 공개(`public`) 선택지, DB 스키마 변경(필요하면 멈추고 보고).

## 1. `packages/core` (테스트 먼저, 커버리지 90%)

- `VISIBILITY_CHOICES = ['followers', 'mutual', 'private'] as const`(세그먼트 순서). `public`은 v3 화면에 넣지 않습니다(D3).
- `visibilityA11y(visibility)` → 문구 키("나만 보기", "맞팔로우 공개", "팔로워 공개").
- `shouldShowFirstPublishNotice(prev, next, seen)` — `private`에서 `mutual`·`followers`로 처음 바꿀 때만 참(D5, SOC-25). 기본 공개 범위를 바꿀 때도 같은 함수(SOC-28).
- 색상 선택기 변환: `hsvToHex`, `hexToHsv`, `normalizeHex`(3·6자리, `#` 유무). 대비 계산은 기존 `goalInk`를 그대로 씁니다.
- `orderTodayPeople(follows)` — `show_on_today`인 사람을 `today_sort_key` 오름차순, **같으면 `created_at` → `followee_id`** 순으로(S3에서 남긴 동시 팔로우 키 겹침 처리). 숨긴 사람 목록도 같은 규칙.
- `moveTodayPerson(list, from, to)` → 새 `today_sort_key`(`keyBetween`). 위/아래 한 칸 이동(VoiceOver 동작)도 같은 함수로.
- 친구의 하루 계산: 기존 하루 목록·캘린더 도장 함수를 **보는 사람의 데이터만으로** 그대로 쓸 수 있는지 확인하고, 필요하면 "읽기 전용 하루" 옵션만 더합니다(새 계산 경로를 따로 만들지 않음). 도장은 볼 수 있는 목표만으로 계산합니다(SOC-33).

## 2. `packages/api`

- **친구 데이터 읽기**: 기존 `listGoals`·`listTodosInRange`·`listRoutines`·`listLogsInRange`는 이미 `userId`를 받습니다(S1 §7). 친구 하루에는 **친구의 `user_id`**를 넘겨 그대로 씁니다. RLS(`can_view_goal`·`can_view_routine`, 건너뛴 루틴 제외)가 걸러 주므로 앱에서 범위를 다시 거르지 않습니다.
  - 친구 쿼리 키는 내 데이터와 섞이지 않게 `['friend', friendId, ...]`로 분리합니다. 내 화면의 낙관적 업데이트·Realtime 캐시와 공유하지 않습니다.
  - 친구 데이터는 **Realtime으로 구독하지 않습니다.** 사람을 고를 때, 앱이 앞으로 올 때, 당겨서 새로고침(iOS)·`⌘R`(macOS)로 다시 불러옵니다. `staleTime` 30초.
  - 지난 미완료 할 일을 오늘로 끌어오는 기능(overdue)은 친구 화면에서 쓰지 않습니다.
- **목표 공개 범위**: `updateGoal`의 변경 항목에 `visibility`를 더하고, `createGoal`은 S2대로 `default_visibility`에서 시작합니다. `mapGoal`에 `visibility`.
- **오늘에 보일 사람**: `fetchTodayPeople(client, me)` — 내 `follows`(`follower_id = me`) + 프로필(RLS가 허용한 것만, `visibleProfile` 적용). `updateTodayPerson(client, me, followeeId, { showOnToday?, todaySortKey? })` — 두 컬럼만 바꿉니다(S1 컬럼 권한). 켤 때는 켠 목록의 맨 아래 키를 새로 붙입니다(SOC-36).
  - 다른 기기의 변경은 앱이 앞으로 올 때 다시 불러옵니다(`follows`는 Realtime에 없음, S1 §9).
- **할 일 신고**: S3의 `report-profile` Edge Function을 `target_kind = 'todo'`도 받게 넓힙니다(함수 이름은 유지하거나 `report`로 바꾸고 이유를 보고). 요청에 `todoId`를 받고, 저장 전에 **사용자 권한으로 그 할 일을 읽을 수 있는지**(= 볼 수 있는지) 확인한 뒤 `target_user_id`를 할 일 주인으로 채웁니다. 메일 제목 `[Nodii report] {reason} — todo of @{handle}`, 본문에 할 일 ID와 제목. 10분 중복 확인은 `(reporter, todo_id)` 기준.
- 훅: `useFriendDay(friendId, range)`, `useGoalVisibility`, `useTodayPeople`·`useUpdateTodayPerson`(낙관적, 실패 시 되돌림), `useReportTodo`.

## 3. 화면

값은 `tokens.md` 토큰만 씁니다. 화면을 만들기 전에 `mobile-designs/v3/`·`desktop-designs/v3/`의 PNG를 열어 봅니다. S4 시안은 캔버스 데스크톱·모바일 탭의 "오늘 친구 · 공개 범위 · 기본 이미지", "오늘 아바타 줄 · 목표 색 선택", "알림 · 사람 하루" 줄과 v3 오늘 화면입니다.

### 3.1 `GoalMark`와 `Avatar` (SOC-24, D16·D23, `components.md`)

- 두 앱에 `GoalMark({ color, visibility, size, friend })` 하나. 나만 = 목표 색 점, 맞팔로우 = 사람 둘(채움), 팔로워 = 사람 하나(채움), 아이콘 색은 `goalInk`. 크기는 그 화면의 동그라미 크기에 비례(이름표 16~17, 목록 줄은 기존 점 크기에 맞춤). `friend`면 범위와 상관없이 점.
- 아이콘 경로는 `@nodii/core` `social-icons.ts`(S2)의 것을 씁니다.
- **기존 목표 동그라미를 전부 `GoalMark`로 바꿉니다.** 오늘 이름표(두 앱), 목표 관리 목록, 보관한 목표, 목표 편집, 할 일·루틴 메뉴 시트 머리말, 루틴 관리·루틴 편집의 목표 이름표, macOS 할 일 줄 메뉴 등. 동그라미가 없는 곳(캘린더 도장, 체크, 루틴 범위 미니 캘린더)은 그대로. 바꾼 곳 목록을 보고에 적습니다.
- 접근성 레이블에 범위: "공부에 할 일 추가, 맞팔로우 공개" / "나만 보기".
- `Avatar`(S2)는 선택 테두리 prop(흰 간격 2.5 + 먹색 2, SOC-31)을 더합니다.

### 3.2 목표 추가·편집: 공개 범위 (SOC-20·21·25·28, D5·D17)

- 순서: 이름 → 색상 → **공개 범위** → 보관/삭제. 세그먼트 `[팔로워 | 맞팔로우 | 나만]`(W/M 전환과 같은 모양, 칸마다 `GoalMark`), 아래 한 줄 설명(`components.md`). 새 목표는 기본 공개 범위(S2)에서 시작.
- 저장은 편집 화면의 [저장]. 오늘 화면 이름표에는 공개 범위 진입점을 두지 않습니다(D17).
- **처음 공개 안내**: `shouldShowFirstPublishNotice`가 참이면 세그먼트를 누른 순간 토스트 "공개하면 지난 기록도 함께 보여요". 본 적 있음은 기기별 저장(첫 실행 안내와 같은 방식). 설정의 기본 공개 범위를 바꿀 때도 같은 안내(SOC-28).
- 시안: iOS `GoalVisSegment`, macOS `GoalVisMac`, 기본 공개 범위 `ProfileDefaultVis`(S2에서 만든 화면 그대로).

### 3.3 iOS 목표 편집 하위 화면과 색상 선택기 (SOC-26·27)

- **iOS**: v2 바텀 시트 대신 목표 관리에서 들어가는 **하위 화면(push, 탭바 숨김)**: "‹ 목표 관리" · 큰 제목 "목표 편집"/"목표 추가" · 이름 · 색상 · 공개 범위 · 보관/삭제 · 하단 고정 [저장]. 오늘 화면 이름표에서 목표를 만드는 길이 있다면 같은 화면으로.
- **무지개 버튼**: 프리셋 11개 뒤 같은 크기(모바일 6열 × 2줄). 프리셋에 없는 색이면 버튼 안에 그 색 작은 동그라미 + 선택 표시.
- 선택기: 채도·밝기 사각형 + 색조 막대 + 미리보기 동그라미 + HEX 입력, 어느 쪽을 바꿔도 따라 바뀜. 기존 HEX 줄은 선택기 안으로.
  - iOS: 바텀 시트(`GoalVisColorSheet`) — 왼쪽 위 [취소], 아래 [이 색으로 하기].
  - macOS: 색상 동그라미 아래로 펼쳐지는 선택기(오른쪽 위 기준 확대 + 높이 펼침 약 0.28초, 동작 줄이기면 바로). 다시 누르면 접힘. 고른 색은 바로 반영, 모달 [저장]으로 확정.
- 사각형·막대는 키보드로도 조절(macOS 화살표, iOS VoiceOver 조절 동작). HEX 칸이 대체 경로입니다.

### 3.4 날짜 줄 · 월 제목 · 고정 줄 · 오프라인 (SOC-30·35·37, D19·D22·D30)

- **월 제목 버튼(D30)**: [오늘] 버튼을 없애고 `2026년 9월` 제목을 누르면 오늘로. 겉모습은 그대로, 접근성 레이블 "2026년 9월, 누르면 오늘로 이동"(`components.md` "월 제목 버튼"). iOS 날짜 줄, macOS 사이드바 캘린더, 사람 하루 페이지 모두.
- **iOS 오늘 탭 위쪽(SOC-30·37)**: 상태 표시줄 → 아바타 줄 → 날짜 줄(월 제목 · [W | M] · 하루 메뉴 슬라이더, 하루 메뉴는 내 하루일 때만) → 캘린더 → 목록. **스크롤 때 고정되는 줄 없음** — 모두 한 덩어리로 스크롤. 하단 탭바는 그대로 떠 있음.
- **macOS(SOC-35, D21)**: 창 맨 위 전체 폭 아바타 줄(46) → 왼쪽 사이드바 캘린더 + 오른쪽 하루 목록 → 하단 탭바. 오른쪽 목록 위에는 날짜 제목·완료 요약·날짜 화살표 없이 하루 메뉴 버튼만 오른쪽 끝(내 하루일 때만). 날짜 이동은 캘린더 클릭·`←/→`·월 제목.
- **오프라인(D19)**: iOS 오프라인 띠(`MobileOffline`)를 없애고, 오프라인에서 쓰기를 시도하면 "오프라인이라 저장할 수 없어요" 토스트. 쓰기 진입점은 숨기거나 비활성으로 두지 않습니다.
- 소셜 꺼짐 경로: v2 오늘 화면 그대로(아바타 줄 없음). 단 월 제목 버튼·고정 줄 없음·오프라인 토스트는 v2 모양에도 적용할지 보고에서 제안하세요(기본: 소셜 꺼짐이면 v2 그대로).

### 3.5 아바타 줄과 친구의 하루 (SOC-30~35, D14·D18, iOS `SocialFriendsA1` · macOS `DeskSocialFinal`)

- **아바타 줄**: 맨 앞 "나"(항상), 그 뒤 켠 팔로잉을 `orderTodayPeople` 순서로, 마지막 칸 **≡ 목록**(테두리 원 + "목록"). 가로 스크롤, 목록 칸도 함께 스크롤. iOS 52 + 12px 이름, macOS 46. 활동 배지·링 없음.
- 고른 사람: `Avatar` 선택 테두리 + 굵은 먹색 이름, 레이블 "민수의 하루, 보는 중". 날짜 줄 제목은 그대로(이름을 쓰지 않음).
- 사람을 누르면 캘린더·목록이 그 사람 것으로 바뀌고, "나"로 돌아옵니다. **선택한 날짜는 유지**(SOC-33). 고른 사람은 앱을 다시 열면 "나"로 돌아갑니다(저장하지 않음).
- **읽기 전용(SOC-32)**: 목표 이름표의 `+`, 밀기, 길게 누르기 메뉴, macOS 호버 `⋯`·우클릭 메뉴, 끌어 옮기기, 하루 메뉴, 할 일 추가 입력을 **숨깁니다**(비활성이 아니라 없음). 체크도 누를 수 없고 상태만 보입니다. `GoalMark`는 점(friend). 끝낸 줄 오른쪽 하트 자리는 S5까지 비워 둡니다.
  - 예외: §3.8의 할 일 신고 메뉴.
- 볼 수 있는 목표가 하나도 없으면 목록 자리에 "공개한 목표가 없어요"(캘린더 도장도 비어 있음).
- 고른 사람을 그새 언팔로우·차단했거나 상대가 차단·정지되면 "나"로 돌아가고 그 칸은 사라집니다.
- 친구 데이터를 불러오는 동안 기존 로딩 모양(스켈레톤 등)을 그대로 쓰고, 실패하면 목록 자리에 "불러오지 못했어요" + [다시 시도].

### 3.6 오늘에 보일 사람 (SOC-36, iOS `SocialFriendsManage` · macOS `DeskSocialFinalManage`)

- ≡ 목록 칸에서 들어가는 **하위 화면**(시트 아님). iOS: "‹ 오늘" + 제목 "오늘에 보일 사람", 탭바 숨김. macOS: 오른쪽 하루 목록 자리에 "‹ 오늘" + 큰 제목, 사이드바 캘린더와 아바타 줄은 그대로.
- 맨 위 검색칸 "팔로잉 중에서 이름이나 ID로 찾기"(내 팔로잉 안에서만, 앱에서 거름).
- 첫 구역: "나"(항상 맨 앞, "항상 맨 앞에 보여요", 스위치·손잡이 없음) + 켠 사람(40 `Avatar` · 이름 · `@ID` · 스위치 · ≡ 손잡이). 구역 머리글·설명 문구 없음. 둘째 구역: "숨긴 사람 · N" + 끈 사람(스위치만).
- 켜면 켠 목록 맨 아래로, 끄면 숨긴 목록으로. 끌어서 순서 바꾸기(iOS 손잡이, macOS 마우스). 손잡이에 VoiceOver "위로 옮기기 / 아래로 옮기기" 동작, macOS는 손잡이에 포커스 후 `⌥↑/⌥↓`.
- 스위치 iOS 40×24(누르는 영역 44), macOS 34×20.
- 저장은 바뀔 때마다 바로(낙관적). 팔로잉이 0명이면 "아직 팔로우한 사람이 없어요" + [친구 찾기](S3 화면).

### 3.7 사람 하루 페이지 본문과 머리 접힘 (SOC-38, D25·D29, iOS `SocialPersonFinal`·`SocialPersonFinalCollapsed` · macOS `MacNotifyPerson`)

- S3의 다른 사람 프로필 아래에 **§3.5와 같은 친구 하루 컴포넌트**(날짜 줄 · 캘린더 · 읽기 전용 목록)를 붙입니다. 아바타 줄·하루 메뉴는 없습니다.
- 이 페이지의 날짜 선택은 페이지 안에서만 유지되고, 닫아도 오늘 탭 날짜에 영향이 없습니다. 처음 열면 오늘.
- **iOS 머리 접힘(D25)**: 맨 위에서는 가운데 정렬 머리(84 아바타 · 닉네임 · `@ID` · 소개 · `FollowButton` 140). 스크롤하면 아바타 84→44 왼쪽으로, 닉네임·ID가 아바타 오른쪽으로, 버튼이 작은 크기로 오른쪽 끝으로 옮겨 가 **한 줄 머리**, 소개는 흐려지며 사라짐. 접힌 머리는 "‹" 줄 아래 고정 + 아래 얇은 선. 스크롤 위치에 맞춰 연속 보간(`tokens.md`의 접힘 표), 동작 줄이기면 두 상태 사이를 바로 바꿈.
- **macOS**: 접지 않는 한 줄 머리(S3) 아래 왼쪽 월 캘린더 · 오른쪽 읽기 전용 목록. 탭바는 들어온 탭이 선택된 채로.
- 팔로우하지 않는 사람은 "공개한 목표가 없어요"가 보통입니다(v3는 전체 공개 없음).

### 3.8 친구 할 일 신고 (SOC-62)

- 친구의 하루(§3.5·§3.7)에서 할 일 줄을 iOS는 길게 누르기, macOS는 우클릭(또는 줄 호버 `⋯`)하면 **"신고하기" 한 항목만 있는 메뉴**가 열립니다. 읽기 전용 규칙(SOC-32)의 유일한 예외입니다.
- S3 신고 시트를 재사용합니다(제목 "할 일 신고", 위에 할 일 제목 한 줄 `muted`, 사유 다섯 가지, 기타 입력, "이 사람 차단하기" 스위치).
- 루틴 줄은 신고 대상이 아닙니다(S1 `reports.target_kind`는 `profile`·`todo`뿐) — 메뉴를 열지 않습니다.

## 4. 문구 (i18n)

- 한국어·영어 카탈로그에 함께: 공개 범위 세그먼트·설명·처음 공개 토스트, 색상 선택기, 월 제목 레이블, 오프라인 토스트, 아바타 줄 레이블, 오늘에 보일 사람, 빈 상태, 할 일 신고. 화면에는 "ID", 코드에는 `handle`.
- 영어 세그먼트: `Followers | Mutuals | Only me`.

## 5. 테스트

- `packages/core`: §1 함수 전부. 특히 `orderTodayPeople`의 동점 처리, `moveTodayPerson` 경계, HSV↔HEX 왕복, 처음 공개 안내 조건.
- `packages/api`: 친구 쿼리가 친구 `user_id`로 나가고 내 캐시 키와 섞이지 않음, `updateTodayPerson`이 두 컬럼만 보냄, 할 일 신고 함수(볼 수 없는 할 일 거부, `target_user_id` 채움, 10분 중복).
- pgTAP: 스키마 변경이 없으므로 기존 346개 그대로. RLS 동작은 S1 테스트가 맡습니다.
- 앱(두 앱): `GoalMark` 세 상태와 friend 점, 세그먼트·처음 공개 토스트(한 번만), iOS 목표 편집 push, 색상 선택기(HEX 입력 → 미리보기), 월 제목 → 오늘, 아바타 줄 선택·날짜 유지·읽기 전용(숨김 확인), 오늘에 보일 사람 켜기/끄기/순서/VoiceOver 동작, 사람 하루 페이지 날짜가 오늘 탭과 독립, 할 일 신고 메뉴, 소셜 꺼짐 경로 그대로.

## 6. 완료 기준

로컬 Supabase + 두 개발 앱, 세 계정(A·B·C)으로(`pnpm db:social-on`):

- [ ] A가 목표 셋을 각각 나만·맞팔로우·팔로워로 둔다. B는 A를 팔로우만, C는 A와 맞팔로우. → B는 팔로워 목표의 할 일·루틴만, C는 맞팔로우·팔로워 목표를, 둘 다 나만 목표는 못 본다. 캘린더 도장도 같은 기준. 건너뛴 루틴 기록은 안 보인다.
- [ ] A가 목표 공개 범위를 바꾸면 B·C 화면이 다시 불러올 때 반영된다. 처음 공개 토스트는 기기마다 한 번만.
- [ ] 동그라미가 쓰이던 모든 화면에 `GoalMark`가 나온다(보고에 목록). 친구 화면에서는 점만.
- [ ] iOS 목표 편집이 하위 화면으로 열리고, 두 앱에서 무지개 버튼으로 직접 고른 색이 저장된다.
- [ ] 월 제목을 누르면 오늘로 간다(오늘 탭, macOS 사이드바, 사람 하루 페이지).
- [ ] 아바타 줄에서 사람을 바꿔도 날짜가 유지되고, 친구 화면에서 쓰기 동작이 전부 숨겨진다.
- [ ] "오늘에 보일 사람"에서 끈 사람은 아바타 줄에서 빠지고, 정한 순서가 다른 기기(다른 앱)에서 앞으로 가져올 때 같이 보인다.
- [ ] 사람 하루 페이지에 캘린더·목록이 나오고 iOS 머리가 스크롤로 접힌다. 동작 줄이기에서는 바로 바뀐다.
- [ ] 친구 할 일 신고가 `reports`(`target_kind = 'todo'`)에 쌓이고 dry-run 로그가 남는다.
- [ ] 두 앱 모두 소셜 꺼짐 경로가 그대로.

## 7. 하지 말 것

- 앱에서 공개 범위를 다시 계산해 친구 데이터를 거르지 않습니다(RLS가 기준). 거꾸로, 화면에서 숨기는 것으로 보안을 대신하지 않습니다.
- 친구 데이터를 내 캐시·낙관적 업데이트·Realtime 구독과 섞지 않습니다.
- 반응 하트·`react` 호출·알림 생성(S5), 푸시(S6).
- `public` 선택지 노출, 스키마·RLS 변경, `follows`를 Realtime에 넣는 일.
- 테스트 시간 제한을 늘리거나 워커 수를 줄여 CI를 통과시키는 일.
- 원격 Supabase 적용, 운영 빌드·TestFlight 업로드(사람이 함).

## 8. 이 지시서에서 정한 것 (보고 때 다시 확인)

1. 친구 데이터는 기존 repository에 친구 `user_id`를 넘겨 읽고, Realtime 없이 선택·앞으로 올 때·새로고침으로 다시 불러온다.
2. 반응 하트는 S5에서 붙이고, S4에서는 자리를 비워 둔다.
3. `today_sort_key`가 같으면 `created_at`, 그다음 `followee_id`로 정렬한다.
4. 아바타 줄에서 고른 사람은 저장하지 않는다(앱을 다시 열면 "나").
5. 할 일 신고는 친구 화면의 할 일 줄 메뉴 하나로만 들어가며, 읽기 전용 규칙의 유일한 예외다. 루틴은 신고 대상이 아니다.
6. 할 일 신고는 S3 Edge Function을 넓혀 처리한다.
7. 소셜 꺼짐이면 오늘 화면은 v2 모양을 유지한다(월 제목 버튼 등 v2 적용 여부는 보고에서 제안).
