# 모바일 화면 스펙 (iOS)

> v2(Expo iOS) 전용입니다. 데스크톱 화면은 `screens.md`, 공통 값은 `tokens.md`·`components.md`를 그대로 씁니다.
> 요구사항 ID는 `docs/01-requirements.md`, 단계는 `docs/11-v2-plan.md` §3 기준.
> 각 화면 이름 옆의 괄호는 디자인 캔버스 "Nodii 디자인"의 **모바일 (iOS)** 페이지 아트보드 이름입니다. 기준 크기는 390×844(iPhone 13/14)입니다.
> **v3 소셜(2026-11-11)**: 바뀐 화면에는 "v3"를 붙였고, 새 화면은 §2-1 "v3 소셜 화면"에 있습니다(근거 `docs/16-v3-social-plan.md`). 소셜이 꺼져 있으면(`social_enabled = false`) 탭바·아바타 줄 없이 v2 화면 그대로입니다.

## 0. 원칙

모바일은 **새 디자인이 아니라 같은 디자인의 다른 몸**입니다.

데스크톱에서 **그대로 가져오는 것** (새로 만들지 않습니다)

- `tokens.md`의 색·글꼴·모서리·모션 값 전부. 색은 목표 색만 가지고 나머지는 먹과 회색입니다.
- 목표 이름표: `chip` 회색 알약 + `GoalMark`(나만은 목표 색 점, 공개한 목표는 범위 아이콘, v3) + `goalInk` 글자 + 먹색 `+`. 체크는 **싹이**(새싹) 모양: 안 한 일은 `box`로 채운 동그란 씨앗, 끝내면 끝내면 목표 색으로 채우고 표시는 `checkColor` (디자인 시스템 v2).
- 캘린더 도장(역시 싹이 모양, 다 끝낸 날만 잎이 돋음): 다 끝낸 날은 `stampFill`(그날 끝낸 목표 색 블록) + 잎 + 흰 체크 / 일부 끝낸 날은 씨앗만 `stampFill`로 채우고 남은 개수를 흰 글자로 / 하나도 못 끝낸 지난날·오늘은 `box`에 개수 / 하나도 못 끝낸 앞날·빈 날은 `stamp-soft`. 자세한 규칙은 `components.md` 캘린더 칸.
- 할 일 줄의 구성(체크 · 제목 · 끝낸 줄은 취소선 없이 `ink-2`), 먹색 알약 기본 버튼, 알약 세그먼트, 알약 실행 취소 토스트, 확인 창.
- 문구는 `screens.md`를 따르되, 사용자 확정으로 달라진 모바일 로그인 문구는 아래 `MobileLogin`을 따릅니다.

모바일에서 **바꾸는 것** (v2 계획 §2.3)

| 데스크톱 | 모바일 | 이유 |
| --- | --- | --- |
| 사이드바 캘린더(380px 고정) | 주간 스트립, W / M으로 월간 전환 | 폭이 없습니다 |
| 사이드바는 고정, 목록만 스크롤 | 캘린더도 목록과 함께 스크롤 | 세로 공간 |
| 호버로 드러나는 `⋯` | 왼쪽/오른쪽 밀기 + 줄 탭 | 호버가 없습니다 |
| 우클릭 컨텍스트 메뉴 | 할 일 줄 탭 → 바텀 액션 시트 | 우클릭이 없습니다 |
| 시트·모달(창 위에서 내려옴) | 바텀 시트(아래에서 올라옴) | iOS 관례 |
| 날짜 헤더(큰 제목 + 개수 요약) | 없음. 날짜는 캘린더가 알려 줍니다 | 세로 공간 |
| 단축키(`⌘N`, `←/→`) | 없음. 대신 날짜는 스트립 탭과 좌우 스와이프 | 키보드가 없습니다 |
| 키보드 포커스 링(`ink` 2px) | 없음. 입력 중 표시는 먹색 테두리와 캐럿 | 터치만 씁니다 |

**할 일 추가는 데스크톱과 똑같습니다.** 목표 이름표의 `+`를 누르면 그 목표 자리에 입력 줄이 열립니다. 하단 고정 추가 바나 떠 있는 `+` 버튼은 두지 않습니다.

## 1. 공통 규칙

**safe area** — 위 47pt(상태 표시줄), 아래 34pt(홈 인디케이터)를 비웁니다. 하단 고정 바는 콘텐츠 영역 아래 34pt를 더한 높이를 차지하고, 스크롤 영역에는 그만큼 아래 여백을 둡니다. 스크롤 내용이 고정 바 밑으로 사라지게 두지 않습니다. v3 탭바가 있는 화면은 탭바 높이만큼 더 둡니다(`tokens.md` §9).

**터치 영역** — 누를 수 있는 것은 모두 44×44pt 이상입니다. 글리프 자체는 작아도(체크 박스 24px, 아이콘 20px) 바깥을 음수 margin으로 넓혀 44pt를 채웁니다. 서로 다른 동작 사이는 8pt 이상 띄웁니다.

**누름 피드백** — 모든 누를 수 있는 요소에 120ms 안에 보이는 반응(투명도 0.55 또는 `scale(0.88)`)을 둡니다. 레이아웃을 흔드는 반응은 금지입니다. `prefers-reduced-motion`에서는 transition을 끕니다.

**글자 크기** — 본문 16px(데스크톱 15px보다 한 단 큽니다), 큰 제목 28px/-0.7px, 보조 13~14px. 12px 미만은 쓰지 않습니다. Dynamic Type을 켠 기기에서 줄이 깨지지 않게 높이는 `min-height`로 둡니다.

**내비게이션 (v3)** — 하단 탭바 `오늘 | 알림 | 프로필`(아이콘만, D13). 탭마다 자기 화면 스택을 갖고, 관리 화면은 각 탭 안에서 밀어 넣습니다(push). 하위 화면에서는 탭바를 숨깁니다. 설정은 프로필 탭의 톱니에서 들어갑니다(D27). 뒤로 가기는 왼쪽 위 글리프 + 라벨("‹ 설정")과 가장자리 스와이프 둘 다 됩니다. 실제 탭바는 Expo Router native tabs를 먼저 검토하고, 시안의 떠 있는 알약은 그것이 안 될 때의 모양입니다(계획서 §5).

_v2까지는 탭 막대가 없었습니다. 그 규칙은 v3에서 위로 바뀝니다._

**바텀 시트** — 위 모서리 22, 손잡이 36×5(`mix(bg, ink, 0.2)`), 뒤는 `scrim`. 시트 안의 취소는 왼쪽 위 글자 버튼, 저장은 오른쪽 위 굵은 글자 버튼입니다. 시트를 아래로 밀면 닫히고, 입력 중이면 "저장하지 않고 닫을까요?"를 먼저 묻습니다.

**제스처 대체 경로** — 밀기로 되는 일은 **반드시** 메뉴 시트에도 있습니다(할 일은 줄을 탭해서 엽니다). 손 떨림이나 접근성 설정으로 밀기를 못 하는 사람이 막히면 안 됩니다.

**포커스 표시** — 파란 포커스 링은 쓰지 않습니다. 터치 기기에는 키보드 포커스가 없고, 데스크톱에서 온 링이 목표 색과 부딪힙니다. 입력 중인 칸은 1.5px 먹색 테두리와 목표 색 캐럿으로만 알립니다. 누름 피드백이 "지금 이걸 눌렀다"를 대신합니다.

**상태 표시줄** — 흰색으로 고정하지 않습니다. 바로 아래 구역의 배경을 그대로 이어받습니다(v2에서는 모든 화면 바탕이 `bg` 하나라 상태 표시줄도 `bg`이고, 시트가 덮을 때만 스크림을 따릅니다). 시계와 배터리 글자색은 `ink`입니다.

**접근성** — 라이트·다크 모두 본문 4.5:1 이상(실제로 16.4~17.8:1), 목표 이름표 글자 4.5:1 이상, 체크 표시 3:1 이상을 `goalInk`·`checkColor`가 보장합니다. 아이콘 단독 버튼에는 `accessibilityLabel`을 답니다. 구분선은 두 테마에서 모두 보이는 `line`을 씁니다.

## 2. 화면

### 로그인 (`MobileLogin`)

- 데스크톱 `Login`과 같은 2단계(이메일 → 6자리 코드)입니다. **이메일 단계의 문구·배치는 사용자 결정(2026-10-27)에 따라 `mobile-designs/v1/로그인.png`를 따릅니다.** 데스크톱 로그인 문구는 `screens.md`에서 별도로 정합니다.
- 위에 싹이 4개(퍼플·핑크·블루 새싹 + `box` 빈 씨앗)를 30pt 간격으로 표시합니다. 별도 작은 “Nodii” 줄 없이 **“Nodii 시작하기”** 제목(30/800, 자간 -1)을 바로 둡니다. 브랜드와 제목 사이는 24pt입니다.
- 설명(16/400, 행간 1.5)은 **“이메일로 받은 6자리 코드로 로그인해요. 처음이면 가입도 함께 돼요.”**입니다. 제목 아래 12pt, 설명 아래 24pt 여백을 두고 이메일 라벨·입력칸·버튼 순서로 이어집니다.
- 좌우 여백은 24pt. safe area 안의 스크롤 콘텐츠에 위 16pt·아래 64pt(48+16) 여백을 두고 전체 묶음을 세로 가운데에 배치합니다. 작은 화면·큰 글자·키보드에서는 내용이 스크롤되어야 합니다. 화면 높이에 고정된 위치를 쓰지 않습니다.
- 입력칸 높이 52, 모서리 14. 입력 중에는 1.5pt 먹색 테두리와 캐럿만 씁니다(파란 링 없음). 기본 버튼 **“코드 받기”**는 가로 전체, 높이 54, 모서리 999입니다. 입력칸과 버튼 사이는 16pt입니다. 빈 이메일에서는 기존처럼 버튼을 비활성화합니다.
- 버튼 아래 32pt에 `muted` 도움말(13/500, 행간 1.5)을 둡니다: **“코드는 10분 동안 쓸 수 있어요. 메일이 안 보이면 스팸함도 확인해 주세요.”** 도움말은 일반 이메일 단계에서만 표시하고 코드 입력·심사 계정 비밀번호 단계에서는 숨깁니다.
- 코드 단계도 사용자 결정(2026-10-27)에 따라 데스크톱과 같은 제목 **“코드를 보냈어요”**와 설명 **“{email}으로 보낸 6자리 코드를 입력해 주세요. 메일이 안 보이면 스팸함도 확인해 주세요.”**를 씁니다. 이메일은 `ink` 700, 나머지는 `ink-2` 16/400입니다. 강제 줄바꿈 없이 긴 이메일·문장도 화면 폭에 맞춰 흐릅니다.
- 코드 단계의 로그인 버튼 아래는 **왼쪽 “다른 이메일로”**, **오른쪽 재전송** 순서입니다. 대기 중에는 **“1:00 뒤에 다시 받을 수 있어요”**처럼 `분:초` 안내(`muted` 13/500·고정폭 숫자)를 표시하고, 0초가 되면 **“코드 다시 받기”** 글자 버튼이 나타납니다. 매초 안내를 자동으로 읽어 주지 않습니다.
- 두 보조 동작은 회색 채움 없는 글자 버튼으로, `ink-2` 16/400·최소 44pt 터치 영역과 누름 피드백을 유지합니다. 하단 줄은 8pt 간격으로 배치하고, 폭·큰 글자 때문에 자리가 부족하면 다음 줄로 이어집니다. 재전송 안내는 오른쪽 정렬입니다.
- 코드 입력의 **“인증 코드” 라벨은 화면에 표시하지 않습니다**(사용자 결정, 2026-10-27). 단일 `TextInput`의 **“6자리 인증 코드” 접근성 레이블**은 유지하며, 시각용 6칸은 접근성 트리에서 숨겨 중복으로 읽히지 않게 합니다.
- 52pt 높이의 6칸 입력·`autocomplete="one-time-code"`·6자리 자동 제출·오류 후 재입력·60초 재전송 제한·다른 이메일로 돌아가기·심사 계정 흐름은 유지합니다.
- 키보드가 올라오면 화면을 위로 밀어 입력칸을 띄웁니다(M1).

### 오늘 (`MobileToday`, 다크는 `MobileTodayDark`) · v3

```
┌──────────────────────────────┐
│ 9:41                   ▮▮ ▮  │  상태 표시줄 47 (고정)
│ (나) (민수) (지은) (현우) (≡) │  아바타 줄 52 + 이름 (v3)
│ 2026년 9월          [W M] ⫶  │  날짜 줄 48 (월 제목 = 오늘 버튼, ⫶ = 하루 메뉴)
│ 일 월 화 수 목 금 토          │  주간 스트립
│ ✓  1  ✓  2  4  2             │   도장 30
│ 13 14 15 16 ⬤17 18 19        │   날짜 알약
│ (⚇ 공부 +)                    │  목표 이름표 36, GoalMark(⚇ = 맞팔로우 아이콘) + 이름 + `+`
│  ☑ 영어 단어 30개              │  줄 52
│  ☐ OS 과제 3장 정리            │
│ (●할 일 +)                    │
│  ☐ 장보기                     │
│        ( 오늘 · 알림 · 프로필 ) │  떠 있는 탭바 (v3)
└──────────────────────────────┘
```

- **고정되는 줄이 없습니다**(SOC-37). 상태 표시줄을 빼면 아바타 줄 · 날짜 줄 · 캘린더 · 목록이 한 덩어리로 스크롤됩니다. 탭바만 떠 있습니다. _v2의 "고정되는 것은 상태 표시줄과 상단 줄뿐" 규칙은 v3에서 바뀝니다._
- **아바타 줄**(SOC-30, `AvatarRow`): 맨 앞 "나", "오늘에 보일 사람"에서 켠 팔로잉을 정한 순서대로, 마지막 칸 ≡ 목록. 넘치면 가로 스크롤(목록 칸도 같이). 사람을 누르면 캘린더·목록이 그 사람 것(읽기 전용)으로 바뀌고, 고른 날짜는 유지합니다(SOC-31~33).
- **날짜 줄**: 왼쪽 월 제목(22/800) — 누르면 오늘로 갑니다(D30, `[오늘]` 버튼 없음). 오른쪽에 [W | M] · 하루 메뉴(슬라이더 글리프, D22). 설정 글리프는 없습니다(프로필 탭으로 옮김).
  - [W | M]은 주간·월간 전환입니다. `chip` 알약 트랙 위에 고른 쪽만 `ink` 원 + `bg` 글자로 띄웁니다.
  - 하루 메뉴는 내 하루일 때만 보입니다(SOC-32).
- 친구의 하루: 이름표 `+`·밀기·길게 누르기·줄 탭 메뉴가 없고, 끝낸 줄 오른쪽에 하트(SOC-32, `HeartButton`). 이름표의 `GoalMark`는 범위와 상관없이 점입니다. 볼 수 있는 목표가 없으면 "공개한 목표가 없어요".
- 큰 날짜 제목과 "N개 중 M개 완료" 요약은 두지 않습니다. 선택한 날짜는 스트립의 먹색 알약이, 남은 개수는 그날의 도장이 알려 줍니다.
- 주간 스트립은 `bg` 바탕 그대로, 구분선 없이 여백으로 목록과 나눕니다. 칸마다 요일(일 `sun`, 토 `sat`) · 도장 · 날짜 알약입니다. 좌우로 밀면 주가 넘어갑니다.
- 할 일과 루틴은 **같은 모양**입니다. 반복 아이콘은 두지 않습니다(ROUT-05, 요구사항 v1.3).
- 지난 미완료 가져오기 배너는 두지 않습니다(하루 메뉴로 모은 결정 그대로, 요구사항 F3).
- 할 일 추가는 목표 이름표의 `+`뿐입니다(`MobileAdd` 참고). 하단 추가 바도, 떠 있는 `+`도 없습니다.
- 빈 날에도 안내 문구 없이 활성 목표 이름표의 `+`로 바로 추가합니다.

### 월간 펼침 (`MobileMonth`)

- 날짜 줄의 [W | M]에서 M을 고른 상태입니다. **날짜나 월 제목(오늘로 이동, D30)을 눌러도 M 선택과 월간 격자를 유지합니다**(2026-10-28 사용자 결정). 앞뒤 달 날짜를 고르면 해당 날짜의 월을, 월 제목을 누르면 오늘이 속한 월을 표시하고 그날의 목록을 갱신합니다. W를 명시적으로 고르면 주간 스트립으로 돌아가며, 주간에서 날짜/오늘을 골라도 W를 유지합니다.
- 7열에 **해당 월에 필요한 4~6주만** 표시합니다(2026-10-27 사용자 결정). 설정한 주 시작 요일을 기준으로 1일을 포함한 주부터 말일을 포함한 주까지이며, 다음 달 날짜만 있는 불필요한 끝 주는 생략합니다. 6주가 필요한 달은 6주를 모두 보여 줍니다.
- 칸 높이는 공통 스펙의 66입니다. 칸마다 도장 + 날짜 알약이고, 첫/마지막 주에 포함된 이번 달 밖의 날짜도 선택할 수 있으며 투명도는 0.4입니다.
- 표시 주수와 별개로 월별 조회·집계·캐시 범위는 기존 42칸을 유지합니다. 데이터 조회 범위를 줄이거나 쿼리 키를 바꾸지 않습니다.
- 선택한 날은 먹으로 채운 알약, 오늘은 먹 테두리 알약입니다(데스크톱과 같은 규칙).
- 격자 역시 고정이 아닙니다. 아래 목록과 함께 스크롤되어, 올리면 목록이 넓어집니다.
- 달 이동은 격자를 좌우로 밀어서 합니다. 이전·다음 달 화살표는 두지 않습니다(M3).

### 할 일 추가 (`MobileAdd`)

데스크톱과 같은 방식입니다. 별도 추가 화면이 아니라 **그 목표 자리에 입력 줄이 열립니다.**

- 목표 이름표의 `+`를 누르면 그 목표의 목록 맨 아래에 입력 줄이 생깁니다. 줄 배경은 `chip`, 왼쪽에 빈 체크 박스 자리, 캐럿은 그 목표 색입니다.
- 키보드가 올라오고, 그 위에 액세서리 줄(높이 48)이 붙습니다. 왼쪽은 날짜 버튼("오늘 · 9월 17일", 누르면 날짜 시트), 오른쪽은 [추가].
- Enter로 추가하면 줄이 비워진 채 그대로 남아 다음 입력을 받습니다. 빈 채로 Enter나 바깥을 누르면 닫힙니다.
- 입력 중 파란 링은 없습니다. 먹색 테두리와 목표 색 캐럿만 씁니다.
- 목표를 잘못 골랐으면 닫고 다른 이름표의 `+`를 누릅니다. 입력 줄 안에서 목표를 바꾸지는 않습니다(데스크톱과 동일).

### 메뉴 시트 (`MobileMenu`)

데스크톱 우클릭 메뉴와 **같은 항목**입니다.

- 항목: 이름 수정 · 날짜 옮기기("캘린더에서 옮길 날짜를 고릅니다") · 오늘만 건너뛰기("루틴은 그 날짜만 비워 둡니다") · 삭제(`danger`).
- 아래에 테두리만 있는 [취소]를 따로 둡니다.

### 날짜 고르기 시트 (`MobileDatePick`, M3)

세 곳이 **같은 시트 하나**를 씁니다: 줄 밀기 [옮기기], 줄 메뉴 "날짜 옮기기", 추가 시트의 날짜 줄. 하루 메뉴의 "미완료 할 일 다른 날로 옮기기"도 같습니다.

- 머리말에 무엇을 옮기는지 적습니다. 한 개면 할 일 제목, 묶음이면 "미완료 할 일 3개".
- 빠른 선택 줄: [오늘] · [내일] · [다음 주]. 높이 44, 알약, 고른 것 없이 누르면 바로 실행합니다.
- 그 아래 월간 격자. `MobileMonth`의 격자를 **그대로 씁니다**(필요한 4~6주, 칸 높이 66, 도장 + 날짜 알약, 이번 달 아닌 날 0.4). 이 시트도 표시 주수만 달라지고 조회·캐시는 42칸을 유지합니다.
- 날짜를 누르면 **바로 옮기고 닫습니다.** [확인] 버튼을 두지 않습니다(데스크톱 날짜 팝오버와 같은 약속, v1.2 결정).
- 같은 날짜를 고르면 아무 일도 하지 않고 닫습니다. 옮기면 실행 취소 토스트가 뜹니다.

### 하루 메뉴 (`MobileDayMenu`, M3)

데스크톱 `DayMenu`(`components.md`)와 **같은 항목·같은 순서**입니다. 진입점만 다릅니다.

- 진입점은 **날짜 줄 오른쪽의 슬라이더 글리프**입니다(v3, D22. v2의 `⋯`를 바꿨습니다). 배너나 숨은 제스처로 두지 않는다는 2026-10-11 결정은 그대로입니다. 지난 날짜·앞날에서도 같은 자리에 있고, 친구의 하루를 볼 때는 숨깁니다.
- 바텀 시트 항목: 지난 미완료 할 일 N개 가져오기 · 미완료 할 일 다른 날로 옮기기 · (구분선) · 미완료 할 일 전체 삭제(`danger`).
- 쓸 수 없는 항목은 **숨기지 말고 비활성**으로 두고 이유를 보조 설명으로 답니다("오늘 화면에서만 쓸 수 있어요").
- 전체 삭제는 개수를 적은 확인 창을 거칩니다(TODO-12). 세 동작 모두 실행 취소 토스트가 붙습니다.
- 완료한 할 일과 루틴은 세 동작 모두 건드리지 않습니다.
- 각 줄 56pt, 왼쪽 20px 글리프, 아래에 테두리만 있는 [취소] — `MobileMenu`와 같은 모양입니다.

### 제스처 (`MobileGestures`)

규칙을 보여주는 설명 보드입니다. 구현 기준은 이 줄들입니다.

- **왼쪽으로 밀기** → [옮기기](`chip`, 먹 글자) · [삭제](`danger-fill`, 흰 글자). 옮기기는 날짜 고르기 시트로, 삭제는 실행 취소 토스트로 이어집니다(TODO-04, 05).

- **길게 눌러 끌기** (할 일, TODO-06) 0.4초 → 줄이 살짝 커지고 진동 한 번, 그대로 위아래로 끌어 놓으면 같은 목표 안에서 순서가 바뀝니다. 루틴은 자리를 지키고 옮긴 할 일 한 행만 갱신합니다. 끌지 않고 떼면 아무 일도 일어나지 않습니다 — 순서 바꾸기와 헷갈리지 않도록 할 일의 `MobileMenu`는 줄을 탭해서만 엽니다(2026-11-02 사용자 요청).

- 보기: 주 시작 요일(일/월) · 테마(자동/라이트/다크).
- 목표와 루틴: 목표 관리 `›` · 루틴 관리 `›`.
- 정보: 버전 · 계정 삭제(`danger` 글자 + "목표, 할 일, 루틴, 팔로우 기록을 모두 지워요"). 확인 창은 개수를 적고 이해 체크를 켜야 버튼이 켜집니다(AUTH-06, SOC-70).
- 단축키 구역은 없습니다.

### 다크 (`MobileTodayDark`)

- 라이트와 같은 구조에 다크 토큰만 바꿔 끼웁니다. 따로 그린 화면이 아닙니다.
- 확인한 값: 본문 16.4:1, 보조 7.0:1, 목표 이름표 글자 4.57~4.84:1, 체크 표시 3.37~6.72:1.
- 다크에서는 카드에 `inset 0 0 0 1px line`을 더해 배경과 구분합니다.

### 첫 실행 안내 (`MobileFirstRun`, M6)

- 첫 로그인 뒤 프로필을 읽어 하루 화면을 열 때 바텀 시트 한 장을 보여 줍니다. 제목 "두 가지만 알아두세요", 오른쪽 [건너뛰기], 아래 먹색 [시작하기].
- 첫 줄은 "할 일 줄을 밀어 보세요"와 오른쪽 완료·왼쪽 옮기기/삭제 설명, 두 번째는 "줄을 눌러 보세요"와 같은 동작을 메뉴로 할 수 있고 길게 눌러 끌면 순서를 바꾼다는 설명입니다. 두 줄 사이 `line`, 안쪽 간격 16, 제목 20, 본문 16/행간 1.5. 기존 `BottomSheet`·버튼·테마·safe area를 씁니다.
- 완료·건너뛰기·배경 탭·아래로 닫기는 모두 기기별 AsyncStorage에 같은 확인 표시를 저장합니다. 로그아웃/계정 전환 후에도 확인 표시는 유지합니다. 저장 실패는 토스트로 알리고 사용을 막지 않습니다.
- 별도 그림이나 새 색은 없습니다. 안내를 건너뛴 뒤에도 줄 탭 메뉴·VoiceOver로 모든 동작을 실행할 수 있습니다(MOB-01). 할 일 순서 바꾸기의 VoiceOver 대체 경로는 보류 중입니다.

### 빈 상태 (`MobileEmpty`, M6)

- 성공적으로 읽은 하루 목록의 항목이 0개여도 빈 날 안내 문구는 표시하지 않습니다. 활성 목표 이름표의 `+`는 유지합니다(2026-10-19 사용자 요청).
- 활성 목표도 없으면 "설정에서 목표를 만든 뒤 첫 할 일을 추가해 주세요."와 [설정] 버튼을 보여 주고 목표 관리로 진입할 수 있게 합니다. 추가 바는 비활성입니다. 가입 시 기본 목표가 생기는 AUTH-04 규칙은 유지하며 서버가 0개를 반환하는 상태도 안내합니다.
- 로딩·조회 실패·오프라인 캐시 없음은 빈 상태로 간주하지 않습니다. 각각 준비 안내·다시 시도·연결 안내를 보여 줍니다.

## 2-1. v3 소셜 화면

시안은 디자인 캔버스의 "소셜 (v3)", "목표 공개 범위", "알림 · 사람 하루 · 사진 자르기", "프로필 탭 · 설정" 페이지에 있습니다. 공통 컴포넌트는 `components.md` "v3 소셜", 값은 `tokens.md` §9.

### 오늘에 보일 사람 (`SocialFriendsManage`, SOC-36)

- 오늘 탭 아바타 줄의 ≡ 목록으로 들어가는 하위 화면(push, 탭바 숨김). 머리 "‹ 오늘" + 가운데 제목 "오늘에 보일 사람".
- 맨 위 검색 칸("팔로잉 중에서 이름이나 ID로 찾기"). 첫 구역: "나"(항상 맨 앞, "항상 맨 앞에 보여요") + 켠 사람들(40 아바타 · 이름 · `@핸들` · 스위치 40×24 · ≡ 손잡이). 둘째 구역: "숨긴 사람 · N" + 끈 사람들(스위치만).
- 손잡이를 길게 눌러 끌어 순서를 바꾸고, VoiceOver에는 "위로 옮기기 / 아래로 옮기기" 동작을 답니다. 구역 머리글 외의 설명 문구는 두지 않습니다.

### 목표 편집 · 추가 (`GoalVisSegment`, 색 선택 `GoalVisColorSheet`, SOC-25~27)

- v2의 바텀 시트 대신 **하위 화면(push)**: "‹ 목표 관리" · 큰 제목 "목표 편집"(추가는 "목표 추가") · 이름 · 색상(6열 × 2줄: 프리셋 11 + 무지개) · 공개 범위 세그먼트 + 설명 한 줄 · 보관/삭제(편집만) · 하단 고정 [저장].
- 무지개를 누르면 색 선택 바텀 시트([취소] · 선택기 · [이 색으로 하기]).
- 공개 범위를 `나만`에서 처음 바꿀 때 한 번만 토스트 "공개하면 지난 기록도 함께 보여요".

### 알림 탭 (`SocialNotifyFinal`, D24, SOC-50~56)

- 큰 제목 "알림"(30/800) → 종류 필터 칩 [전체 · 친구 완료 · 좋아요 · 팔로우] → "오늘" · "이번 주" · 그 이전 구간의 `NotificationRow`.
- 안 읽음 표시·배지·"모두 읽음"이 없습니다. 아래로 당기면 새로 고칩니다.
- 빈 상태: "아직 알림이 없어요" (문구 제안).

### 사람 하루 페이지 (`SocialPersonFinal`, 접힘 `SocialPersonFinalCollapsed`, 버튼 `SocialPersonFinalButtons`, SOC-38, D25)

- 하위 화면(push, 탭바 숨김). 머리 "‹ {들어온 화면}" + 오른쪽 `⋯`(신고·차단).
- `ProfileHeader` 펼침(84 아바타 · 닉네임 · `@핸들` · 소개 · `FollowButton` 140) → 스크롤하면 한 줄로 접혀 "‹" 줄 아래에 고정.
- 그 아래 오늘 탭 복사본: 날짜 줄(월 제목 = 오늘 버튼 · [W | M], 하루 메뉴 없음) · 캘린더 · 읽기 전용 목록 + 하트. 날짜 선택은 이 페이지 안에서만 유지됩니다.
- 볼 수 있는 목표가 없으면 "공개한 목표가 없어요".

### 프로필 탭 (`ProfileTabB`, 빈 상태 `ProfileTabEmpty`, D27, SOC-08)

- 맨 위 줄 오른쪽: 사람+(친구 찾기) · 톱니(설정), 각 44pt 글리프.
- `ProfileHeader`(84 아바타 · 닉네임 · `@핸들` · 소개) → 숫자 두 칸(팔로잉 · 팔로워, 누르면 목록) → [프로필 편집] [프로필 공유].
- 팔로잉 0명이면 버튼 아래 초대 카드(`chip` 묶음, 모서리 20. 시안의 `#F7F8FA`는 토큰이 아니므로 `chip`을 씁니다): "친구와 함께 해 볼까요?" · "링크를 보내면 친구가 바로 나를 팔로우할 수 있어요. 공개한 목표만 보여요." · [초대 링크 보내기](주요). 소개가 없으면 그 줄을 뺍니다.
- 그 아래 본문은 v3에서 비웁니다(D27).

### 친구 찾기 (`ProfileSearch`, SOC-08·10)

- 하위 화면. 맨 위 검색칸(자동 포커스) + [취소], 아래 "ID가 정확히 맞는 사람이 먼저 나와요" 13 `muted`, 결과 줄(44 아바타 · 이름 · `@핸들` · `FollowButton`). 줄을 누르면 사람 하루 페이지.
- "ID로 검색 허용"을 끈 사람은 결과에 나오지 않습니다(SOC-06).

### 팔로잉 · 팔로워 목록 (SOC-12)

- 하위 화면. 줄: 40 아바타 · 이름 · `@핸들` · `FollowButton`. 팔로워 목록 줄을 왼쪽으로 밀거나 줄 메뉴에서 "팔로워에서 내보내기"(확인 창, 실행 취소 없음).
- 시안은 macOS(`MacProfileM1`)만 있습니다. 모바일은 같은 줄을 세로 목록으로 둡니다.

### 새 목표의 기본 공개 범위 (`ProfileDefaultVis`, SOC-28)

- 하위 화면 "‹ 설정". 제목 "새 목표의 기본 공개 범위" + 설명 "새 목표를 만들 때 이 범위로 시작해요. 이미 있는 목표는 바뀌지 않아요." + 세 줄 라디오(아이콘 칸 40 · 이름 · 설명 · 오른쪽 체크): 나만 · 맞팔로우 · 팔로워.

### 사진 자르기 (`SocialCropFinal`, SOC-04, D26)

- 프로필 편집에서 사진을 고르면 전체 화면: 위 [취소] · "사진 자르기" · [완료](굵게) → 자르기 판(끌기·핀치) → 확대 막대 → 화면 아래쪽 "미리보기"와 80 · 52 · 36 미리보기 → "기본 이미지로 되돌리기"(사진이 있을 때만).
- [완료]하면 기기에서 160px·480px JPEG(품질 0.8)로 만들고 EXIF를 지운 뒤 올립니다.
