## 1. 한 줄 요약

**팔로우한 사람의 하루를 오늘 탭에서 그대로 열어 보고, 끝낸 일에 반응을 남긴다.** 무엇을 보여 줄지는 목표마다 내가 정한다. macOS와 iOS에 동시에 출시한다.

## 2. 확정한 결정

| # | 결정 | 이유 |
|---|---|---|
| D1 | 관계는 **팔로우**(한쪽 방향), **수락 없이** 바로 팔로우된다 | 다음 업데이트의 전체 공개로 자연스럽게 넓힐 수 있다 |
| D2 | 공개 범위는 **목표마다** 설정: `나만 / 맞팔로우 / 팔로워 / 전체 공개` | 사용자가 목표 단위로 보여 줄 정도를 고른다 |
| D3 | **전체 공개는 enum 값만 v3에 넣고 화면에는 3단계만** 보여 준다. 화면은 다음 업데이트에서 연다 | v3에는 모르는 사람이 내 목표를 볼 경로(둘러보기 등)가 없어 차이가 작다 |
| D4 | 친한 친구 목록은 **만들지 않는다** | 맞팔로우가 "내가 고른 사람들" 역할을 한다. 필요해지면 `나만`과 `맞팔로우` 사이에 끼워 넣는다 |
| D5 | 공개한 목표는 **과거 기록까지 전부** 보인다 | 구현이 단순하다 |
| D6 | 업데이트 시 **기존 목표는 모두 `나만`**으로 시작한다 | 지금까지 "나만 보는 앱"으로 쓴 데이터다 |
| D7 | 좋아요는 **반응(`type`)으로 설계**하고 v3에서는 `like`만 쓴다 | 마스코트 이모티콘을 스키마 변경 없이 얹는다 |
| D8 | 완료를 취소해도 **받은 반응은 남는다** | 구현 부담이 가장 적다 |
| D9 | 프로필 사진: 처음엔 **기본 프로필 이미지**, 프로필 설정에서 **사진 업로드**로 바꿀 수 있다 (v3 포함) | |
| D10 | 친구 완료 알림은 **기본 꺼짐**. 전체 켜기/끄기 + 사람별 켜기/끄기 | 팔로잉이 늘면 알림이 너무 많아진다 |
| D11 | **댓글은 넣지 않는다** | 신고·관리 부담이 가장 큰 기능 |
| D12 | 프로필 링크는 **바뀌지 않는 초대 토큰**, 핸들(ID) 변경은 **쿨다운** | 핸들을 바꿔도 공유한 링크가 깨지지 않는다 |
| D13 | 하단 탭바 3개: **`오늘 | 알림 | 프로필`**, 아이콘만 표시 | 오늘 탭에서 친구의 하루를 보므로 세 번째 탭은 관리하는 곳이다 |
| D14 | 친구의 하루는 **오늘 탭 위쪽의 프로필 줄**에서 사람을 골라 보고, 캘린더·목록이 그 사람 것으로 바뀐다 | 기존 화면을 읽기 전용으로 재사용한다 |
| D15 | **macOS와 iOS 동시 출시** | 한쪽만 먼저 내면 탭바 부재·푸시·요청을 못 보는 사용자 문제가 생긴다 |
| D16 | 공개 범위는 **목표 색 동그라미 자리를 범위 아이콘으로 바꿔** 표시한다(시안 A3). 팔로워 = 사람 하나, 맞팔로우 = 사람 둘, 나만 = **동그라미 그대로**. 아이콘 색은 **이름표 글자색(`goalInk`)**. 목표 이름 옆에 동그라미가 들어가는 **모든 곳**에 같은 규칙을 쓴다 | 이름표 길이가 그대로이고, 소셜을 안 쓰는 사람에게는 지금 화면과 같다. 글자색은 모든 목표 색에서 4.5:1 이상을 보장한다 |
| D17 | 공개 범위는 **목표 편집 화면에서만** 바꾼다. 오늘 화면의 이름표 길게 누르기 같은 별도 진입점은 두지 않는다 | 공개 범위는 자주 바꾸는 값이 아니다. 진입점을 하나로 두어 단순하게 유지한다 |
| D18 | 오늘 탭 위쪽 순서는 **아바타 줄 → 날짜 줄(`2026년 9월` · W/M) → 캘린더**(시안 `SocialFriendsA1`). 고른 사람은 **먹색 테두리**, 활동 배지는 없다. 줄 마지막은 **≡ 목록 버튼**이고, 누르면 **"오늘에 보일 사람"** 하위 화면으로 들어가 보일 사람과 순서를 정한다 | 투두메이트와 같은 익숙한 얼굴 줄. 누구를 보는지는 테두리와 이름으로 충분해서 날짜 제목에 이름을 다시 쓰지 않는다. 팔로잉이 늘어도 사용자가 고른 사람만 보인다 |
| D19 | 모바일 **오프라인 띠(`MobileOffline`)는 v3에서 뺀다.** 오프라인에서 쓰기를 시도하면 기존 저장 실패 토스트 대신 "오프라인이라 저장할 수 없어요" 토스트로 알린다. 쓰기 진입점은 숨기거나 비활성으로 두지 않는다 | 화면 맨 위 공간을 늘 차지할 만큼 자주 생기는 상황이 아니고, iOS 상태 표시줄이 이미 연결 상태를 보여 준다. 고정 줄이 없어진 v3 구조(SOC-37)에서 띠를 둘 자리도 애매하다. 필요해지면 다시 넣는다 |
| D20 | **macOS 탭바는 창 하단의 고정된 탭바 공간**으로 둔다. 리퀴드 글라스처럼 떠 있는 탭바가 아니라 콘텐츠와 겹치지 않는 별도 줄이다(투두메이트 데스크톱처럼 모바일과 같은 하단 탭 구조) | 모바일과 같은 위치·순서라 두 앱을 오가도 헷갈리지 않는다. 콘텐츠를 가리지 않아 스크롤 끝 여백 계산이 필요 없다 |
| D21 | **macOS 오늘 화면**(시안 `DeskSocialFinal`·`DeskSocialFinalManage`): 창 맨 위 **전체 폭 아바타 줄**(46px) → 그 아래 왼쪽 사이드바 캘린더 + 오른쪽 하루 목록 → 창 하단 탭바. 탭바는 아이콘만, **고른 아이콘 뒤에 회색 알약**. 오른쪽 목록 위의 **날짜 제목·"N개 중 M개 완료" 요약·이전/다음 날 화살표는 없앤다**(날짜는 캘린더의 먹색 알약이 알려 주고, 이동은 캘린더 클릭과 `←/→` 단축키). 그 자리 오른쪽 끝에는 하루 메뉴 버튼만 둔다. "오늘에 보일 사람"은 **오른쪽 목록 자리에 열리는 하위 화면**("‹ 오늘")이다 | 위쪽 전체 폭이라 한 번에 더 많은 사람이 보인다. 탭바는 모바일과 같은 표시 방식. 하위 화면은 모바일과 같은 흐름이고 사이드바를 그대로 둔다 |
| D22 | **하루 메뉴 버튼의 아이콘은 미트볼(`⋯`) 대신 슬라이더 아이콘**(기존 설정 버튼 아이콘)으로 바꾼다. 모바일 날짜 줄과 데스크톱 모두 같다. 설정 진입점은 프로필 탭으로 옮겨 아이콘이 겹치지 않게 한다. 하루 메뉴는 내 하루를 볼 때만 보이고 친구를 볼 때는 숨긴다(SOC-32) | 모양 대신 "하루를 정리하는 도구"라는 뜻이 드러난다 |
| D23 | **기본 프로필 이미지는 무채색 싹이**(시안 `DefaultAvatar` P1): `chip` 회색 원 안에 회색 싹이 씨앗(씨앗 `#C3C7CF`, 잎 `#AEB3BD`). 모든 사람이 같은 이미지이고, 크기는 원 지름의 약 62%로 살짝 아래에 둔다. 다크 테마 값은 `chip #1E2026` · 씨앗 `#4A4F59` · 잎 `#5B616C`, 고른 사람 테두리는 바탕 간격 + `ink #F3F4F6`. iOS 탭바 다크는 `#1A1C21` · 고른 탭 `#2B2E35`(캔버스 "스타일 기초" 소셜 묶음) | "색은 목표에서만 나온다"는 규칙을 지킨다. 사람 구분은 이름과 사진에 맡긴다 |
| D24 | **알림 탭은 날짜별 한 줄 목록**(시안 `SocialNotifyFinal`, N1 바탕) 위에 **종류 필터 칩** [전체 · 친구 완료 · 좋아요 · 팔로우]를 둔다. 줄마다 안 읽음 표시(점·굵은 글씨)와 탭의 읽지 않은 개수 배지를 두지 않고, 그래서 "모두 읽음" 버튼도 없다. 서버에도 읽음 상태를 저장하지 않는다 | 카드형(N2)보다 오늘 탭의 담백한 목록 톤과 맞고, 필터로 원하는 종류만 빠르게 본다. 알림은 시간순으로 훑는 화면이라 줄 단위 읽음 상태가 주는 정보가 적다 |
| D25 | **사람 하루 페이지 머리는 맨 위에서 가운데 정렬(P2), 스크롤하면 왼쪽 한 줄(P1)로 접힌다**(시안 `SocialPersonFinal`·`SocialPersonFinalCollapsed`). "나를 팔로우해요" 보조 표시는 두지 않고, 대신 **팔로우 버튼이 관계에 따라 세 가지**로 보인다(인스타그램 방식, 시안 `SocialPersonFinalButtons`): [팔로우] · [맞팔로우] · [팔로잉]. 같은 규칙을 알림 줄·팔로잉/팔로워 목록·검색 결과에도 쓴다 | 처음엔 그 사람이 누구인지 크게 보여 주고, 하루를 읽기 시작하면 머리가 비켜서 할 일이 많이 보인다. 상대가 나를 팔로우한다는 사실은 버튼 이름 하나로 충분히 전해진다 |
| D26 | **사진 자르기는 밝은 화면 + 확대 막대**(시안 `SocialCropFinal`, C2 바탕). iOS·macOS가 같은 화면을 쓴다 | 앱 톤을 유지하고, 핀치가 없는 macOS에서도 그대로 쓸 수 있다. 실제로 보일 크기를 미리 확인할 수 있다 |
| D27 | **세 번째 탭 이름은 "프로필"**(아이콘만 보이고 접근성 레이블·문서에 쓴다). 구성은 맨 위 줄 오른쪽 **설정(톱니) 버튼** → 프로필 머리(사람 하루 페이지와 같은 컴포넌트) → 친구 찾기까지이고, **그 아래 본문은 v3에서 비워 둔다.** 기존 오늘 화면의 설정 진입점은 이 탭으로 옮긴다(D22 확정) | 본문 자리는 다음 업데이트의 기록·통계(§10)를 위해 남겨 둔다. 설정은 "나"에 관한 것이라 프로필에 두는 게 자연스럽고, 오늘 화면의 아이콘 겹침도 사라진다 |
| D28 | **macOS 프로필 탭은 왼쪽 프로필 + 오른쪽 하위 화면**(시안 `MacProfileM1`). 왼쪽 380 칸에 프로필 머리, 오른쪽 칸은 기본으로 팔로잉/팔로워 목록이고, 친구 찾기·설정도 오른쪽 칸에 열린다 | "오늘에 보일 사람"(D21)과 같은 방식이다. 본문이 비어 있는 v3에서도 넓은 창이 비어 보이지 않고, 기록·통계가 생기면 오른쪽 칸의 첫 화면으로 쓴다 |
| D29 | **macOS 알림 탭은 가운데 한 줄 목록**(시안 `MacNotifyMN1`). 모바일 알림(D24)을 약 600 폭으로 창 가운데에 두고, 줄 펼치기·필터·팔로우 버튼이 같다. 아바타·이름을 누르면 창 전체가 **사람 하루 페이지**(시안 `MacNotifyPerson`)로 바뀌고 "‹ 알림"으로 돌아온다 | 모바일과 같은 동작이라 익히기 쉽고, 알림은 훑고 펼쳐 보는 화면이라 목록 하나로 충분하다 |
| D30 | **[오늘] 버튼을 없애고, 월 제목(`2026년 9월`)을 누르면 오늘로 이동한다.** 모바일 날짜 줄, macOS 사이드바 캘린더, 사람 하루 페이지 모두 같다. 제목은 겉모습을 바꾸지 않는 버튼이고 접근성 레이블은 "2026년 9월, 누르면 오늘로 이동", macOS는 마우스를 올리면 "오늘로 이동" 툴팁. 오늘을 보고 있을 때 눌러도 아무 일도 없다. macOS `⌘T`는 그대로 | 날짜 줄에 아바타·W/M·하루 메뉴가 모이면서 알약 하나를 덜어 낸다. 월 제목은 "지금 어디쯤인지"를 알려 주는 자리라 누르면 오늘로 돌아오는 동작이 자연스럽다 |
| D31 | **프로필 만들기는 `ProfileSetupH1`, 프로필 편집은 `ProfileEditE1`.** 만들기는 제목·설명 → 넉넉한 간격 → 미리보기 줄(64 아바타 · 닉네임 · @ID) → 닉네임·ID 칸 → [시작하기]. 편집은 사진 + 항목 줄(닉네임 · ID · 소개 `›`)이고 줄마다 칸 하나짜리 편집 화면, [완료]가 바로 저장한다. ID 쿨다운 중에는 자물쇠와 남은 날. **사용자에게 보이는 글은 "핸들" 대신 "ID"**(코드·DB 이름은 `handle` 유지) | 미리보기가 입력하는 대로 바뀌어 "남에게 이렇게 보인다"가 바로 보인다. 항목별 편집은 iOS 설정 앱처럼 익숙하고, ID처럼 규칙이 많은 칸의 안내를 넉넉히 보여 줄 수 있다. "핸들"은 낯선 말이라 "ID"가 더 친근하다 |
| D32 | **macOS 프로필 탭 기본 화면은 오른쪽 칸 없이 가운데에 내 프로필만**(iOS와 같은 구성, 팔로잉 0명이면 두 버튼 아래 초대 카드). 프로필 편집·설정·친구 찾기·팔로잉/팔로워를 누르면 프로필 칸이 왼쪽 380 칸으로 미끄러지고 오른쪽 칸에 그 화면이 열린다(M1 구조). 닫으면 다시 가운데. 사람+는 iOS·macOS 모두 톱니 옆에 항상 둔다 | 아무것도 고르지 않았을 때 빈 오른쪽 칸이나 목록이 먼저 보이지 않아 깔끔하고, 두 앱의 첫 화면이 같아진다. 고른 뒤에는 M1처럼 프로필을 보면서 오른쪽에서 일할 수 있다 |

## 3. 요구사항 (SOC)

### 3.1 프로필

- **SOC-01** 프로필 항목: 닉네임, 핸들(ID), 짧은 소개글, 프로필 사진. 처음엔 기본 이미지(무채색 싹이, D23)로 시작하고, 사진을 지우면 다시 기본 이미지로 돌아간다. 닉네임은 1~20자, 어떤 글자든 쓸 수 있고 중복을 허용한다.
- **SOC-02** 핸들(ID) 규칙:
  - 3~20자. 소문자 영문·숫자·`_`·`.`만, **영문으로 시작**. 마침표 연속(`..`)·끝 마침표 금지.
  - 대소문자 구분 없이 전역 유니크. 입력은 소문자로 바꿔 저장한다.
  - 예약어 금지: `docs/16-v3-moderation/reserved-words.csv`(`nodii`·`노디`·`admin`·`official`·`support`·`운영자`·`관리자`·`고객센터` 등 33개). 핸들과 닉네임이 예약어와 **정확히 같으면** 막는다. 목록은 서버 테이블에 둔다.
  - 바꾼 뒤 **30일** 동안 다시 바꿀 수 없다. 버린 핸들은 **30일간 다른 사람이 쓸 수 없게** 묶어 사칭을 막는다.
  - 이메일에서 기본 핸들을 만들지 않는다(이메일 노출 방지). 소셜을 처음 쓸 때 사용자가 직접 정한다(SOC-03).
- **SOC-03** 소셜 기능을 처음 쓸 때 핸들을 정한다. 소셜을 쓰지 않는 사용자는 지금처럼 혼자 쓸 수 있다.
- **SOC-04** 프로필 사진 업로드:
  - 사진을 고르면 **원형 자르기 화면**이 열린다(D26, 시안 `SocialCropFinal`). 흰 배경 위 위쪽 줄에 [취소] · "사진 자르기" · [완료].
    - 가운데 둥근 사각형(먹색 배경) 안에 사진, 그 위에 원형 틀. 틀 밖은 어둡게 덮는다.
    - 사진을 끌어서 위치를 맞추고, 핀치(iOS)·트랙패드 핀치(macOS) 또는 아래 **확대 막대**(− 돋보기 · 막대 · + 돋보기)로 확대·축소한다. 두 플랫폼 모두 막대가 있다.
    - 화면 아래쪽에 "미리보기" 제목과 **세 크기 미리보기**: 프로필 80 · 아바타 줄 52 · 목록 36. 끌거나 확대할 때 바로 바뀐다.
    - 맨 아래 "기본 이미지로 되돌리기"(사진이 있을 때만).
  - 완료하면 기기에서 정사각형으로 잘라 두 크기로 만든다: **160px**(아바타 줄·목록, 52pt@3x) · **480px**(프로필 화면). JPEG 품질 0.8.
  - HEIC은 JPEG로 변환하고, 움직이는 이미지(GIF 등)는 받지 않는다. 원본은 10MB까지.
  - **EXIF(촬영 위치 등)는 반드시 지운다.**
  - 바꿀 때마다 새 파일 이름으로 올리고 예전 파일은 지운다(캐시 문제 방지). 기본 이미지로 되돌릴 수 있다.
- **SOC-05** 프로필 링크 공유: `nodii.app`의 초대 링크(바뀌지 않는 토큰). 앱이 있으면 앱의 프로필로, 없으면 App Store 안내 페이지로 간다.
- **SOC-06** "ID로 검색 허용" 끄기. 끄면 검색에는 안 나오고 링크로만 찾을 수 있다.
- **SOC-07** 소개글: **최대 80자, 두 줄까지**(줄바꿈 1번). 링크는 눌리지 않는 일반 글자로 보여 준다(스팸 방지).
- **SOC-08** **프로필 탭**(D27):
  - **모바일**(시안 `ProfileTabB`): 맨 위 줄 오른쪽에 **친구 찾기(사람+)** · **설정(톱니)** 버튼. 둘 다 하위 화면(push)으로 열린다(시안 `ProfileSearch`·`ProfileSettings`·`ProfileDefaultVis`).
  - **macOS**(D28, 시안 `MacProfileM1`·`MacProfileM1Settings`·`MacProfileM1Search`): 왼쪽 380 칸 위쪽에 사람+·톱니, 그 아래 프로필 머리. 오른쪽 칸은 기본으로 팔로잉/팔로워 목록(왼쪽 숫자 칸이 선택 표시, 위쪽 [팔로잉 n | 팔로워 n] 전환)이고, 사람+·톱니를 누르면 친구 찾기·설정이 오른쪽 칸에 "‹ 뒤로"와 함께 열린다. 설정은 두 단. `⌘,`로도 설정을 연다.
  - **프로필 머리:** 사람 하루 페이지(SOC-38)와 같은 컴포넌트. 가운데 정렬 84 아바타 · 닉네임 · `@핸들` · 소개글, 스크롤하면 한 줄로 접힌다(D25).
    - 숫자는 **두 칸**(큰 숫자 + 아래 "팔로잉"/"팔로워"). 누르면 각 목록(SOC-12)으로 간다. 팔로워 목록 줄의 `⋯`에 팔로워 내보내기.
    - 버튼 **[프로필 편집]**(사진 → 자르기 화면 SOC-04, 닉네임, 핸들, 소개글) · **[프로필 공유]**(초대 링크 SOC-05).
  - **친구 찾기:** 검색창 하나, ID가 정확히 맞는 사람을 먼저 보여 준다. 줄 오른쪽 버튼은 D25 규칙. 줄을 누르면 사람 하루 페이지.
  - **팔로잉 0명**(시안 `ProfileTabEmpty`): 버튼 아래에 초대 카드("친구와 함께 해 볼까요?" · [초대 링크 보내기], SOC-05). 소개글이 없으면 그 줄은 빠진다.
  - 그 아래 본문은 v3에서 비워 둔다(기록·통계는 §10).
  - **설정에 새로 들어가는 것:**
    - 알림: 친구 완료 알림 전체·사람별(D10, SOC-51), 새 팔로워·반응(SOC-53)
    - 개인정보: 새 목표의 기본 공개 범위(SOC-28), "ID로 검색 허용"(SOC-06), 차단 목록(SOC-61)
    - 계정: 핸들 변경(SOC-02), 로그아웃, 계정 삭제
    - 기존 설정 항목은 그대로 둔다.

### 3.2 팔로우

- **SOC-10** ID 검색 또는 프로필 링크로 팔로우한다. 수락 없이 바로 된다.
- **SOC-11** 언팔로우. 언팔하면 그 사람의 `맞팔로우` 목표도 더 이상 볼 수 없다는 안내를 확인 창에 둔다(상대가 나를 볼 수 있는 범위도 함께 줄어든다).
- **SOC-12** 팔로잉·팔로워 목록. 팔로워 목록에서 **팔로워 내보내기**(차단하지 않고 팔로우를 끊기)를 할 수 있다.
- **SOC-13** 팔로우 요청 횟수 제한(서버 rate limit)으로 스팸 팔로우를 막는다. 한 사람이 **1시간에 30명**까지 새로 팔로우할 수 있다.

### 3.3 공개 범위

- **SOC-20** 목표마다 공개 범위를 고른다. v3 화면에는 `나만 / 맞팔로우 / 팔로워` 3개.
- **SOC-21** 문구는 범위를 정확하게 설명한다. 예: 팔로워 = "나를 팔로우하는 누구나". 수락이 없으므로 팔로워 공개를 "아는 사람에게만"으로 오해하지 않게 한다.
- **SOC-22** 새 목표의 기본 공개 범위는 `나만`(제안).
- **SOC-23** 루틴과 할 일은 자기 목표의 공개 범위를 따른다. 건너뛴 루틴은 친구에게 보이지 않는다.
- **SOC-24** 어떤 목표가 어떤 범위인지 한눈에 보인다(D16, 시안 `SocialVisA3`·`SocialVisIcons`).
  - 목표 이름 옆의 **색 동그라미 자리**에 범위 아이콘을 넣는다. 오늘 화면 이름표는 `아이콘 · 목표 이름 · +` 그대로이고, 이름표 길이는 늘지 않는다.

    | 범위 | 표시 |
    |---|---|
    | 나만 (기본값) | 지금의 목표 색 동그라미 그대로 |
    | 맞팔로우 | 사람 둘 아이콘 (채운 모양) |
    | 팔로워 | 사람 하나 아이콘 (채운 모양) |
    | 전체 공개 (다음 업데이트) | 지구 아이콘 |

  - **아이콘 색은 이름표 글자색(`goalInk`)과 같다.** 나만의 동그라미는 지금처럼 목표 색(`goal`)이다.
  - 아이콘 크기는 16~17px로 기존 10px 동그라미보다 크다. 다른 화면에서는 그 화면의 동그라미 크기에 맞춰 비례로 키운다.
  - **적용 범위: 목표 이름 옆에 동그라미가 들어가는 모든 곳.** 오늘 화면 목표 이름표(모바일·데스크톱), 목표 관리 목록, 보관한 목표, 목표 편집, 할 일·루틴 메뉴 시트 머리말, 루틴 관리·루틴 편집의 목표 이름표 등. 동그라미가 없는 곳(캘린더 도장, 체크, 루틴 범위 미니 캘린더)은 바꾸지 않는다.
  - 접근성 레이블에 범위를 함께 읽어 준다. 예: "공부에 할 일 추가, 맞팔로우 공개". 나만은 "나만 보기"로 읽는다.
  - 친구의 하루를 볼 때(SOC-32)는 친구 목표에 아이콘을 표시하지 않고 동그라미만 쓴다. 친구의 범위 설정은 보는 사람에게 의미가 없다.
- **SOC-25** 공개 범위 변경은 **목표 편집 화면**에서만 한다(D17). 목표 추가 화면에도 같은 구역을 두어 처음부터 고를 수 있게 한다(기본값 `나만`). 시안 `GoalVisSegment`(V2), macOS `GoalVisMac`.
  - 화면 순서: 이름 → 색상 → **공개 범위** → 보관/삭제.
  - 공개 범위는 **알약 세그먼트** `[팔로워 | 맞팔로우 | 나만]`으로 바로 고른다(오늘 탭의 W/M 전환과 같은 모양: 고른 칸은 먹색 바탕 + 흰 글자). 칸마다 범위 아이콘(나만은 목표 색 동그라미)을 함께 둔다. 별도 시트는 쓰지 않는다.
  - 세그먼트 아래 한 줄에 고른 범위의 설명: 팔로워 "나를 팔로우하는 누구나 볼 수 있어요" · 맞팔로우 "나와 서로 팔로우하는 사람만 볼 수 있어요" · 나만 "나만 볼 수 있어요".
  - 저장은 편집 화면의 [저장]을 따른다.
  - 오늘 화면의 이름표는 지금처럼 누르면 할 일 추가(`+`)이고, 길게 누르기 등 공개 범위용 진입점은 두지 않는다.
  - 이전 시안의 공개 범위 시트(`SocialVisSheet`)는 쓰지 않는다.
  - **지난 기록 안내(D5):** `나만`에서 다른 범위(팔로워·맞팔로우)로 **처음 바꿀 때 한 번만** 토스트로 알린다: "공개하면 지난 기록도 함께 보여요". 세그먼트를 누른 순간 띄우고, 확인 표시는 첫 실행 안내(`MobileFirstRun`)처럼 기기별로 저장한다. 그 뒤로는 다시 띄우지 않는다.
- **SOC-26** **목표 편집 화면 형태(iOS).** v2의 바텀 시트 대신 목표 관리에서 들어가는 **하위 화면(push)**으로 바꾼다: "‹ 목표 관리" · 큰 제목 "목표 편집" · 이름 · 색상 · 공개 범위 · 보관/삭제 · 하단 고정 [저장]. 목표 추가도 같은 형태다. macOS는 지금의 모달을 유지한다.
- **SOC-27** **직접 고르는 색상.** 색상 프리셋 11개 뒤에 같은 크기의 **무지개 동그라미 버튼**(직접 고르기)을 둔다(모바일 6열 × 2줄이 꽉 찬다).
  - 선택기: 채도·밝기 사각형 + 색조 막대 + 미리보기 동그라미 + HEX 입력. 어느 쪽을 바꿔도 나머지가 따라 바뀐다. 기존 HEX 입력 줄은 선택기 안으로 들어간다.
  - **iOS:** 무지개 버튼을 누르면 **바텀 시트**로 열린다(시안 `GoalVisColorSheet`). 왼쪽 위 [취소], 아래 [이 색으로 하기].
  - **macOS:** 무지개 버튼을 누르면 버튼에서 펼쳐지는 느낌으로 **색상 동그라미 아래에 선택기가 열린다**(오른쪽 위 기준 확대 + 높이 펼침, 약 0.28초, 동작 줄이기 설정에서는 애니메이션 없음). 다시 누르면 접힌다. 고른 색은 바로 반영되고 모달의 [저장]으로 확정한다.
  - 직접 고른 색이 프리셋에 없으면 무지개 버튼 안에 그 색을 작은 동그라미로 채우고 선택 표시를 한다.
  - 목표 글자색(`goalInk`)과 체크 색은 기존처럼 고른 색에서 계산해 대비를 보장한다.
- **SOC-28** **새 목표의 기본 공개 범위.** 설정 > 개인정보에서 `나만 / 맞팔로우 / 팔로워` 중 고른다(기본값 `나만`). 새 목표를 만들 때 목표 편집의 공개 범위 세그먼트가 이 값으로 시작한다. 이미 있는 목표에는 영향이 없다. 기본값을 `나만`이 아닌 값으로 바꿀 때도 처음 공개 토스트(SOC-25)와 같은 안내를 한 번 보여 준다(제안).

### 3.4 친구의 하루 보기 (오늘 탭)

- **SOC-30** 오늘 탭 맨 위에 **아바타 줄**(D18, 시안 `SocialFriendsA1`).
  - 순서: 상태 표시줄 → 아바타 줄 → 날짜 줄(`2026년 9월` · [W | M], 내 화면에서는 하루 메뉴(슬라이더)까지. 월 제목을 누르면 오늘로 이동, D30) → 주간/월간 캘린더 → 목록. 기존 "상단 줄"의 내용이 아바타 줄 아래의 날짜 줄로 내려간다.
  - 칸마다 52px 원형 아바타 + 아래 12px 이름. 맨 앞은 항상 **"나"**, 그 뒤는 "오늘에 보일 사람"(SOC-36)에서 켠 팔로잉을 정한 순서대로. 넘치면 가로로 스크롤된다.
  - 줄의 **마지막 칸은 ≡ 목록 버튼**(테두리만 있는 원 + "목록"). 누르면 "오늘에 보일 사람" 화면으로 들어간다. 목록 버튼은 따로 고정하지 않고 **아바타 하나처럼 줄과 함께 가로 스크롤**되어, 줄을 끝까지 넘기면 마지막에 나온다. 예: `나 · 민수 · 지은 · 서연 · 현우 · ≡`.
  - 사람을 누르면 캘린더와 목록이 그 사람 것으로 바뀌고, "나"를 누르면 돌아온다.
  - 오늘 무언가 끝낸 사람을 알리는 배지·링 같은 활동 표시는 두지 않는다.
- **SOC-31** 지금 누구의 하루를 보는지는 **아바타의 먹색 테두리**(흰 간격 2.5px + 먹색 2px)와 **굵은 먹색 이름**으로 알린다. 날짜 줄 제목은 그대로 `2026년 9월`이고, 이름을 다시 쓰지 않는다. 접근성 레이블은 "민수의 하루, 보는 중".
- **SOC-32** 친구의 하루는 읽기 전용: 목표 이름표의 `+`, 밀기, 길게 누르기 메뉴, 날짜 줄의 하루 메뉴 `⋯`를 쓸 수 없다(숨긴다). 끝낸 줄 오른쪽에 반응(하트) 버튼이 있고, 누른 하트는 그 목표의 이름표 글자색으로 채운다.
- **SOC-33** 사람을 바꿔도 선택한 날짜는 유지한다. 캘린더 도장은 내가 볼 수 있는 그 사람의 목표만으로 계산한다.
- **SOC-34** 아바타 줄의 순서는 **사용자가 정한 순서**다(SOC-36). 활동 순으로 자동 정렬하지 않는다.
- **SOC-35** macOS는 **창 맨 위 전체 폭**에 아바타 줄(46px 아바타 + 이름, 마지막 칸 ≡ 목록)을 두고, 그 아래에 기존 사이드바 캘린더와 하루 목록을 둔다(D21). 오른쪽 목록 위에는 날짜 제목·완료 요약·날짜 화살표 없이 하루 메뉴 버튼만 오른쪽 끝에 둔다(내 하루일 때만). 날짜 이동은 캘린더 클릭과 `←/→`, 사이드바 월 제목을 누르면 오늘(D30).
- **SOC-36** **"오늘에 보일 사람"** 화면(시안 `SocialFriendsManage`). 아바타 줄의 ≡ 목록 버튼으로 들어가는 **하위 화면**(push)이다. 시트가 아니다.
  - 머리: 왼쪽 "‹ 오늘", 가운데 제목 "오늘에 보일 사람". 하단 탭바는 숨긴다.
  - 맨 위에 팔로잉 검색 칸("팔로잉 중에서 이름이나 ID로 찾기").
  - 첫 구역: "나"(항상 맨 앞, "항상 맨 앞에 보여요", 스위치·손잡이 없음) + 켠 사람들. 줄마다 아바타 40px · 이름 · `@핸들` · 스위치 · ≡ 손잡이. 손잡이를 끌어 순서를 바꾼다. 구역 머리글과 "끌어서 순서 바꾸기" 같은 설명 문구는 두지 않는다.
  - 둘째 구역: 머리글 "숨긴 사람 · N" + 끈 사람들(스위치만, 손잡이 없음).
  - 스위치 40×24(먹색 = 켜짐, `#E6E8EC` = 꺼짐). 보이는 크기만 작고 누를 수 있는 영역은 44pt를 유지한다.
  - 켜면 켠 사람 목록의 맨 아래로, 끄면 숨긴 사람 목록으로 옮긴다. 끄더라도 팔로우는 그대로다(화면에 따로 설명하지 않는다).
  - 새로 팔로우한 사람은 켜진 채로 목록 맨 아래에 추가된다(화면에 따로 설명하지 않는다).
  - 끌기의 대체 경로: 손잡이에 VoiceOver "위로 옮기기 / 아래로 옮기기" 동작을 단다(`12-design-mobile-screens.md` §1 제스처 대체 경로 규칙).
  - 대상은 **팔로잉**(내가 팔로우하는 사람)이다. 팔로워가 아니다.
  - **macOS:** 오른쪽 하루 목록 자리에 열리는 하위 화면("‹ 오늘" + 큰 제목 "오늘에 보일 사람"). 사이드바 캘린더와 위쪽 아바타 줄은 그대로 보이고, 모달이나 팝오버는 쓰지 않는다. 스위치 34×20, 손잡이는 마우스로 끌어 옮긴다.
- **SOC-38** **사람 하루 페이지.** 알림·팔로잉/팔로워 목록·검색 결과 등에서 사람의 프로필(아바타·이름)을 누르면, 그 사람의 하루를 보여 주는 **하위 화면(push)**이 열린다.
  - 내용은 오늘 탭에서 친구를 골랐을 때와 **같은 화면의 복사본**이다(날짜 줄 · 캘린더 · 읽기 전용 목록 · 반응 하트, SOC-32·33). 같은 컴포넌트를 재사용하고 아바타 줄만 없다.
  - 머리: 왼쪽 "‹ 뒤로"(들어온 화면 이름), 그 아래 프로필 머리(아바타 · 닉네임 · `@핸들` · 소개글).
  - **머리 접힘(D25):** 맨 위에서는 가운데 정렬 머리(84 아바타 · 닉네임 · `@핸들` · 소개글 · 140 폭 버튼). 스크롤하면 아바타가 84→44로 줄며 왼쪽으로, 닉네임·핸들이 아바타 오른쪽으로, 버튼이 작은 크기로 오른쪽 끝으로 옮겨 가 **한 줄 머리**가 되고, 소개글은 흐려지며 사라진다. 접힌 머리는 "‹ 뒤로" 줄 아래에 고정되고 아래에 얇은 선이 생긴다. 스크롤 위치에 맞춰 연속으로 보간하고, 동작 줄이기 설정에서는 두 상태 사이를 바로 바꾼다.
  - **팔로우 버튼(D25):** 내가 팔로우하지 않고 상대도 나를 팔로우하지 않으면 [팔로우](먹색), 내가 팔로우하지 않는데 상대가 나를 팔로우하면 [맞팔로우](먹색), 내가 팔로우 중이면 [팔로잉](회색). [팔로잉]을 누르면 언팔로우 확인(SOC-11)을 거쳐 취소한다. 별도의 "나를 팔로우해요" 표시는 두지 않는다.
  - 내가 팔로우하지 않는 사람이면 볼 수 있는 목표가 없을 수 있다. 이때는 "공개한 목표가 없어요" 빈 상태를 보여 준다(v3는 전체 공개가 없으므로).
  - 신고·차단은 머리 오른쪽 `⋯` 메뉴에 둔다(SOC-60·62).
  - **macOS**(D29, 시안 `MacNotifyPerson`): 창 위 "‹ 알림" 아래에 전체 폭 한 줄 머리(64 아바타 · 닉네임 · `@핸들` · 소개글 · 팔로우 버튼 · `⋯`). 넓은 창이라 접지 않는다. 그 아래는 macOS 오늘 화면의 복사본(왼쪽 월 캘린더 · 오른쪽 읽기 전용 목록 + 하트)이고 아바타 줄·하루 메뉴는 없다. 탭바는 들어온 탭이 선택된 채로 둔다.
  - 날짜를 바꿔 보는 것은 그 페이지 안에서만 유지되고, 닫으면 오늘 탭의 선택 날짜에 영향을 주지 않는다.
- **SOC-37** 오늘 탭에는 **스크롤할 때 고정되는 줄이 없다.** 상태 표시줄을 빼면 아바타 줄 · 날짜 줄 · 캘린더 · 목록이 모두 한 덩어리로 스크롤된다. 날짜 줄을 위에 고정하던 기존 규칙(`12-design-mobile-screens.md`의 "고정되는 것은 상태 표시줄과 상단 줄뿐")은 v3에서 바뀐다. 하단 탭바는 그대로 떠 있다.

### 3.5 반응

- **SOC-40** 내가 볼 수 있는 친구의 **완료된** 할 일·루틴에 반응(v3는 좋아요)을 남기고 취소할 수 있다.
- **SOC-41** 반응을 남기는 순간에만 완료 상태를 확인한다. 이후 완료를 취소해도 반응은 남는다(D8).
- **SOC-42** 내 할 일에 받은 반응을 볼 수 있다(누가 남겼는지).

### 3.6 알림

- **SOC-50** 알림 탭: 새 팔로워 · 받은 반응 · 친구의 할 일 완료. **읽지 않은 개수 배지는 두지 않는다**(D24). 앱 아이콘 배지도 쓰지 않는다.
- **SOC-51** 친구 완료 알림은 기본 꺼짐. 전체 켜기/끄기와 사람별 켜기/끄기(D10).
  - 알림 탭에서는 **친구 한 명당 하루 한 줄**로 묶는다. 더 끝내면 그 줄의 숫자를 늘리고 맨 위로 올린다: "민수님이 할 일 3개를 끝냈어요".
  - 푸시는 **같은 친구당 3시간에 최대 1번**, 기기 시간 **밤 11시~아침 8시에는 보내지 않는다.**
  - 같은 할 일을 체크·해제·재체크해도 한 번만 센다.
- **SOC-56** 알림 탭 구성(D24, 시안 `SocialNotifyFinal`): 큰 제목 "알림" 아래 **종류 필터 칩** [전체 · 친구 완료 · 좋아요 · 팔로우](하나만 선택, 기본 전체). 목록은 "오늘" · "이번 주" · 그 이전 구간으로 나눈다. 줄은 40 아바타 · 문장(이름 굵게) · 시간 · 오른쪽 동작이고, **줄 단위 안 읽음 표시는 없다.**
  - 오른쪽 동작: 친구 완료는 펼치기 `⌄`, 반응은 반응받은 목표 동그라미, 새 팔로워는 팔로우 버튼(D25의 세 상태 규칙, 보통 [맞팔로우] 또는 [팔로잉]).
- **SOC-55** 알림 줄의 동작:
  - 친구 완료 알림 줄을 누르면 **그 자리에서 펼쳐져** 그날 끝낸 할 일 목록(목표 동그라미 · 제목 · 반응 하트)이 보인다. 다시 누르면 접힌다. 펼친 목록에서 바로 반응을 남길 수 있다.
  - 줄 안의 **아바타·이름을 누르면** 그 사람의 사람 하루 페이지(SOC-38)가 열린다.
  - 반응 알림 줄은 누르면 반응을 받은 내 할 일의 날짜로 오늘 탭을 연다(제안). 새 팔로워 알림 줄은 그 사람의 사람 하루 페이지를 연다.
- **SOC-52** 친구 완료 알림은 **그 할 일을 내가 볼 수 있을 때만** 만든다(공개 범위·차단 확인).
- **SOC-53** 알림 종류별 켜기/끄기(새 팔로워, 반응).
- **SOC-54** iOS는 원격 푸시, macOS는 앱이 켜져 있을 때 Realtime + 로컬 알림(§6).

### 3.7 안전 (App Store 1.2)

- **SOC-60** 차단: 팔로우 관계가 양쪽 모두 끊긴다. 서로 검색·팔로우·프로필·목표(전체 공개 포함)·반응·알림이 모두 막힌다. 상대에게는 차단 사실이 보이지 않는다.
- **SOC-61** 차단 목록과 차단 해제(프로필 탭 또는 설정).
- **SOC-62** 신고: 프로필(닉네임·사진·소개)과 할 일 제목. 신고하면서 차단도 할 수 있다.
  - 사유: 스팸 / 불쾌한 내용 / 사칭 / 괴롭힘 / 기타(직접 입력).
  - 신고는 `reports`에 쌓이고, 즉시 Resend로 지원 메일함에 알림 메일을 보낸다.
  - **24시간 안에 확인**한다(약관에 명시, 가이드라인 1.2의 적시 대응).
  - 조치 단계: ① 해당 콘텐츠 숨김 → ② 프로필(닉네임·사진·소개)을 기본값으로 초기화 → ③ 계정의 소셜 기능 정지(`profiles.social_suspended_at`).
  - 서로 다른 사용자의 신고가 **3건** 쌓이면 확인 전이라도 프로필 사진·소개를 자동으로 숨긴다.
  - 처음엔 관리자 화면 없이 Supabase Studio의 저장된 쿼리로 처리한다.
- **SOC-63** 이용약관에 부적절한 콘텐츠·악용 금지 조항, 신고 확인 시간, 지원 연락처를 명시한다.
- **SOC-64** 핸들·닉네임·소개에 **금칙어 필터**를 둔다(가이드라인 1.2의 부적절한 콘텐츠 거르기).
  - 목록: `docs/16-v3-moderation/banned-words.csv`(2,373개, 열 `word, match, lang`). 사용자가 준 원본(`slang-source.csv`, 4,240줄)에서 정리했고, 뺀 항목과 이유는 `banned-words-removed.csv`에 있다.
  - 원본에서 뺀 것(1,669개): 중국어·일본어 1,354개(v3 지원 언어 밖이고 상당수가 정치 검열어), 다른 회사·게임·운영 용어 232개, 정치인 이름·정치 성향 표현 31개, 욕설이 아닌 일상어 28개(`hell`, `damn`, `세끼` 등), 정체성 단어 13개(`gay`, `lesbian`, `queer` 등), 예약어로 옮긴 10개. 비하 표현(`fag`, `dyke` 등)은 남겼다.
  - **검사 방식(`match`):**
    - `contains`: 정규화한 문자열에 포함되면 막는다(대부분, 2,182개).
    - `exact`: 공백·기호로 나눈 **단어 하나가 정확히 그것일 때만** 막는다(191개). 일상어와 겹치는 항목이다: 한 글자(`년`·`놈`·`젖`·`엿`·`씹` 등), 영어 3글자 이하(`ass`·`tit`·`cum`), `생리`·`새끼`·`미친`·`시바`·`보지`·`자지`·`발기`·`수간`·`oral`·`sex`·`dick` 등.
    - 확인한 예: "2026년", "청년", "class", "title", "hello", "생리학", "새끼손가락", "시바견", "아버지", "보지마", "시발점", "발기인", "젓가락", "하루 세끼"는 통과하고, "씨발", "개새끼", "shithead", "xx좆xx"는 막힌다.
  - 정규화: NFKC, 소문자. 이모지·기호로 쪼갠 우회(예: `s.e.x`)는 v3에서 따로 막지 않고 신고(SOC-62)로 처리한다.
  - 저장할 때 **서버에서** 검사한다(RPC 또는 트리거). 앱은 입력 중 같은 목록으로 미리 안내만 한다("쓸 수 없는 단어가 들어 있어요"). 어떤 단어가 걸렸는지는 보여 주지 않는다.
  - 목록은 마이그레이션으로 `banned_words` 테이블에 넣고, 이후 추가·삭제도 마이그레이션으로 한다.

### 4.2 공개 범위와 RLS

보는 사람과 주인의 **관계 단계**를 숫자로 매기고, 목표의 공개 범위가 요구하는 단계 이상이면 읽을 수 있습니다.

| 관계 단계 | 값 | | 목표 공개 범위 | 필요한 단계 |
|---|---|---|---|---|
| 없음 | 0 | | `public`(다음 업데이트) | 0 |
| 팔로워 | 1 | | `followers` | 1 |
| 맞팔로우 | 2 | | `mutual` | 2 |
| 본인 | 3 | | `private` | 3 |

- 어느 방향이든 차단이 있으면 단계 계산 전에 거부합니다(전체 공개 포함).
- `can_view_goal(goal_id)`를 `stable` 함수로 두고 `goals`·`todos`·`routines`·`routine_logs`의 **SELECT 정책에만** 추가합니다. 쓰기 정책은 지금처럼 `user_id = auth.uid()` 그대로입니다.
- `follows`·`blocks`에 양방향 인덱스를 둡니다. 친구 화면은 읽기가 크게 늘어나므로 정책 비용을 `EXPLAIN`으로 확인합니다.
- `follows`의 UPDATE 정책은 `follower_id = auth.uid()`이고 `show_on_today`·`today_sort_key`만 바꿀 수 있게 컬럼 권한을 제한합니다(팔로우 대상·시각은 바꿀 수 없음).
- **pgTAP 필수 검사:** A가 B의 `private` 목표를 못 본다 / 팔로워가 `mutual` 목표를 못 본다 / 맞팔이면 `mutual`을 본다 / 언팔 직후 못 본다 / 차단하면 모든 범위가 막힌다 / 친구의 할 일을 수정·삭제할 수 없다 / `public` 값이 있어도 v3 화면 없이 동작이 정의돼 있다 / 팔로우당한 사람은 상대의 `show_on_today`·순서를 바꿀 수 없다.

### 4.3 반응의 대상

루틴은 날짜마다 행이 생기지 않고(가상 전개, ADR-003) 완료하면 `routine_logs (routine_id, date, 'done')`이 생깁니다. 그래서 반응 대상은 둘 중 하나입니다.

- 할 일: `todo_id`
- 루틴: `routine_id` + `date`
- check 제약으로 **정확히 하나만** 채웁니다. unique는 `(reactor_id, 대상, type)`.

주의할 점:

- **`routine_logs`를 외래 키로 참조하지 않습니다.** 완료를 취소하면 로그 행이 물리 삭제되므로(ADR-017) 반응이 함께 지워져 D8과 충돌합니다.
- 반응은 `react` RPC로만 남깁니다. 이 함수가 "볼 수 있는가 + 지금 완료 상태인가"를 확인합니다.
- 반응 취소(내 반응 삭제)는 물리 DELETE를 허용합니다. **ADR-017을 갱신**해야 합니다(`routine_logs`, `reactions` 두 테이블).
- `split_routine`("오늘부터 적용")은 `p_from` 이후 로그를 새 루틴으로 옮깁니다. **같은 범위의 반응도 새 `routine_id`로 옮기도록** 함수를 고치고 pgTAP으로 확인합니다.
- "과거 날짜까지 모두"로 숨겨진 날의 반응은 지우지 않고 함께 숨겨집니다.

## 5. 내비게이션

- 하단 탭바: `오늘 | 알림 | 프로필`, 아이콘만 표시. 아이콘 단독이므로 탭마다 `accessibilityLabel`(오늘 / 알림 / 프로필)을 답니다.
- 오늘 탭 위쪽은 아바타 줄 → 날짜 줄 → 캘린더 순서입니다(D18, SOC-30). 기존 "상단 줄"(월 제목 · 오늘 · W/M · ⋯ · 설정)은 날짜 줄(월 제목 · W/M · 하루 메뉴)로 바뀌고 [오늘] 버튼은 월 제목이 대신하며(D30), 더 이상 위에 고정하지 않습니다(SOC-37).
- 모바일 오프라인 띠(`MobileOffline`)는 v3에서 뺍니다(D19). `12-design-mobile-screens.md`의 해당 절과 요구사항 SYNC-04의 모바일 표시는 v3 설계 때 함께 고칩니다.
- 프로필 탭(D27, SOC-08): 설정 버튼 · 내 프로필 머리(팔로잉·팔로워 숫자, 프로필 편집·공유) · 친구 찾기. 본문은 v3에서 비워 둡니다. 설정·팔로잉/팔로워 목록·프로필 편집은 이 탭의 하위 화면(push)이고, 차단 목록은 설정 > 개인정보에 있습니다. 오늘 화면의 **설정 진입점은 이 탭으로 옮깁니다.**
- "오늘에 보일 사람"은 오늘 탭 안의 하위 화면(push)이고, 들어가면 탭바를 숨깁니다(SOC-36).
- 탭바를 넣으면서 바꿔야 할 기존 규칙: `12-design-mobile-screens.md` §1의 "탭 막대는 두지 않습니다", 실행 취소 토스트 위치(탭바 위로), safe area·하단 여백.
- iOS는 실제 iOS 탭바를 쓰는 Expo Router native tabs를 우선 검토합니다(실험 단계 API라 쓸 SDK에서 상태 확인). 시안의 떠 있는 알약 모양 탭바는 임시입니다.
- macOS는 **창 하단에 고정된 탭바 줄**을 둡니다(D20). 떠 있는 리퀴드 글라스가 아니라 콘텐츠 영역과 위쪽 1px 선으로 나뉜 56px 줄이고, 순서는 모바일과 같은 `오늘 | 알림 | 프로필`입니다. **아이콘만** 쓰고 고른 탭은 아이콘 뒤 회색 알약으로 표시합니다(D21). 마우스를 올리면 "오늘 (⌘1)" 같은 툴팁, 키보드로는 `⌘1`·`⌘2`·`⌘3`.
- 하루 메뉴 버튼의 아이콘은 슬라이더 아이콘이고, 설정 진입점은 프로필 탭으로 옮깁니다(D22). 기존 모바일 상단 줄과 데스크톱 오른쪽 위의 설정 글리프는 없앱니다.

## 6. 플랫폼과 출시

- **서버 먼저:** 스키마·RLS·RPC·pgTAP을 먼저 끝내고, 이후 단계마다 macOS·iOS를 같이 진행합니다.
- **푸시:** iOS는 Expo push(APNs). macOS는 Tauri에서 원격 푸시가 공식 지원되지 않을 가능성이 높아, 앱이 켜져 있을 때 Realtime으로 받아 **로컬 알림 + 배지**로 보여 줍니다.
- **기능 스위치:** `app_config.social_enabled`. 두 앱이 모두 심사를 통과한 뒤 같은 날 켭니다. 켤 때 최소 지원 버전(`min_*_app_version`)도 함께 올립니다.
- **기존 버전 앱:** 내 데이터 쓰기 RLS는 바뀌지 않으므로 그대로 동작합니다. 다만 친구 SELECT 정책이 생기면 `user_id`로 거르지 않는 예전 조회에 친구의 공개 항목이 섞일 수 있습니다(같은 계정으로 v3 앱과 예전 앱을 같이 쓸 때). S1에서 조회에 `user_id` 필터를 넣고(`docs/v3/S1-db.md` §7), 출시 때 최소 지원 버전을 올립니다.
- **비용:** 친구 화면으로 읽기가 늘어납니다. v3 출시 전에 Supabase Pro 전환을 전제로 둡니다(v2 계획 §7-6).
